The intent is one of four: `insert` a new record; `update` when something changed or more is known; `correct` when the recorded value was wrong in the first place (this finds the tasks that read the wrong value); `revoke` when the record should not exist (its history is kept). Put the user's own words in `evidence` (`kind: user_message`); to make the words evidence for a value that did not change, name it in `evidence_by_field`. To clear an optional field, write `null`. Do not write each reading a device produces (heart rate, glucose): record a summary of each activity or day. `replayed: true` in the receipt means this was a repeat and nothing new was written; when a record with the same content really happened again, write it with a different `idempotency_key`. Periods of state tables are `[valid_from, valid_to)`, the end not included: for \"until 11-20 (included)\" pass `valid_to: \"2026-11-21\"`. Without an end, only up to the next recorded change; the receipt says nothing after it was touched. Writing by `entity_key` creates the entity when it does not exist; the receipt lists the keys the table already has, and marks those written alike. `revoke` without a period revokes the whole entity, with a period it leaves that period without a value.
