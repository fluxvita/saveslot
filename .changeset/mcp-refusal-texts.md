MCP refusals that said nothing useful now give their data and a next step: too many evidence segments or premises (the bound and the count), a premise target at its fan-in bound, premises on its own record or in another slot or on an op that cannot carry them, two ops by one source key, a source key held or frozen, a write on an old schema version (what changed and the version to use), a draft on an old version, and a draft that leaves out a field (which fields). Every contract error code is shown as a code. An awaiting-confirmation mark with no proposal no longer ends in an empty "proposed:"; a next change on a day table is said with its last day inclusive; the write description no longer points at a business time the premise mark does not carry; and the schema document's description says how to drop fields and tables and how to write aliases.
