# saveslot · 数据层机制 · 10 字段类型、同值与单位

> 数据层机制的一部分，目录见 [`README.md`](README.md)。文中「…」引用的节可能在同目录的其他文件里，按目录查。

字段的类型怎么取值、两个值什么时候算"相同"、两个键什么时候算写法相近、带单位的数怎么换算与舍入。这些规则被写入校验、同值判断、冲突判定、疑似重复、字面命中与写入回执的提示共用，所以集中在一处。

## 字段类型与取值范围

| 类型 | 是什么 | 取值范围 |
|---|---|---|
| `text` | 文本 | 至多 8 KB（UTF-8），调用方的原文与 NFC 之后的结果都不能超。落账前做 Unicode NFC 规范化；首尾空白、大小写原样保留。须是良构的 Unicode，不得含 NUL（U+0000，PostgreSQL 的 `text` 存不了）。空字符串是一个值，不是空 |
| `integer` | 整数 | 64 位有符号 |
| `decimal` | 小数 | 整数部分至多 18 位；小数位数 `scale` 0–12 |
| `quantity` | 带单位的数 | 数值同 `decimal`；单位取自「单位词表」 |
| `boolean` | 布尔 | — |
| `enum` | 枚举 | 至多 200 个取值，每个至多 64 个字符；区分大小写。取值须是 NFC 规范形式、不含控制字符、首尾不带空白：写入时按同一个字符串比较，声明成别的形式的取值之后永远对不上 |
| `date` | 日历日 | 0001-01-01 至 9999-12-31；按 slot 时区的自然日理解 |
| `zoned_datetime` | 时刻 + IANA 时区 | 毫秒精度；时刻在 UTC 下落在 0001-01-01 至 9999-12-31 |
| `ref` | 指向同一 slot 一张表（可以是它自己所在的表）的一行或一个实体 | 见「写入请求 · 引用字段」 |

- **名字**：slot 名、表名、字段名匹配 `[A-Za-z][A-Za-z0-9_]{0,62}`，在受限 SQL 里直接当标识符写。不得以 `_` 开头；字段名不得是 `valid`、`valid_from`、`valid_to`（写入与查询参数里的保留键）、`row_id`、`entity_id`（`valid_from`、`valid_to` 与这两个同时是受限 SQL 里的系统列，见 [「受限 SQL」](11-restricted-sql.md)「名字」）。违反时编译报 `validation_failed`（`reserved_name`）。
- **名字不分 ASCII 大小写唯一**：slot 名在租户内、表名在 slot 内、字段名在表内，按 ASCII 大小写折叠之后两两不同（`Runs` 与 `runs` 不能并存），违反时编译报 `validation_failed`（`duplicate_name`）。受限 SQL 里不加引号的标识符按不分大小写解析，名字只差大小写就会指向同一个对象，所以唯一性也按不分大小写算。名字本身照写入时的大小写保存与显示。
- **说明**（`description`）至多 500 个字符，内容不限。
- **别名**（`aliases`，表与字段上可选）：至多 8 个，每个至多 64 个字符（与枚举取值的长度上限相同）。内容规则与"不参与名字解析"见「schema 文档格式」。
- 数值在事件与存储里一律是十进制，不用浮点（见「派生规则 · 确定性边界」）。

## 清空字段

- 写入里把字段的值写成 `null`，是清空一个**可选**字段。它是一次**贡献**：值为空，值来源照常是这次写入的证据。
- **必填字段不能清空**：报 `validation_failed`（`required_missing`）。不想要这一行，用撤销。
- 删除重放时，空值贡献与其他贡献一样参与"最后一个仍在的贡献"：它的来源被删，更早的值回来（见「删除 · 重放规则」）。
- 新增时没带的可选字段没有贡献。新增时显式写 `null`，与"原来没有值"同值，按同值规则是无操作或佐证。
- 状态类表上，可选字段在一段区间上为空是"值为空"，不是无值区间；它的 值 ↔ 空 是取值变化，算挡点（见「时间 · 无值区间」）。
- 字面命中对空值记"不适用"。

## 同值判据

"与所见版本同值""值没变""疑似重复命中""按 `entity_key` 定位""按 `external_key` 定位"用的都是这一张表。

| 字段类型 | 同值当且仅当 |
|---|---|
| `quantity` | 换算到字段声明的单位、按 `scale` 舍入后，数值相等（`1.0` 与 `1.00` 相同） |
| `decimal` | 按 `scale` 舍入后数值相等 |
| `integer` | 数值相等 |
| `text` | NFC 规范化之后逐码点相同。不去首尾空白，不折叠大小写 |
| `enum` | 取值相同 |
| `boolean` | 相同 |
| `date` | 同一天 |
| `zoned_datetime` | 同一瞬间**且**时区相同（时区不同，"哪一天"可能不同） |
| `ref` | 指向同一行或同一实体（请求里的临时名先解析成 ID 再比） |
| 空 | 空与空相同；空与任何值不同 |

状态类表上，"同值"另要求在解析出的整个区间上都相同（见「时间 · 用同样的值写」）。

`zoned_datetime` 的"时区相同"比的是规范化之后的时区名：与运行时给出的规范名只差大小写的写法，按规范名记（`asia/shanghai` 记作 `Asia/Shanghai`）；运行时映射成另一个名字的别名（`US/Eastern`），照调用方写的记，与它的规范名（`America/New_York`）暂不算同一个时区。别名与规范名的统一，与钉死时区库是同一份工作，随它一起做。原始值里的时区名一律照调用方写的记。

## 相近的键

按 `entity_key` 写入、键不存在而新建实体时，回执的 `similar_keys` 列出该表里写法与新键相近的已有键（见「时间 · 按 `entity_key` 写入」）。"相近"按下面的判据算，算法版本 `keymatch@1`，随内核发布。

- **它是提示，不是判定**：不进事件，不占规则版本，不改变任何状态。同一份状态、同一个新键、同一个 `keymatch` 版本，结果相同；换一个 `keymatch` 版本可能给出不同的提示，不影响重放。
- **所用的 Unicode 数据随 `keymatch@1` 固定、打包在内核里**：实现时由数据文件生成，不手抄，也不调用操作系统或运行时自带的规范化与语言环境（各运行时的 Unicode 版本可能不同）。NFKC 与大小写折叠用同一个 Unicode 版本。

**第一步，折叠** N(s)，依次做三件事：

| 步骤 | 做什么 | 抹平什么 |
|---|---|---|
| ① | Unicode NFKC 规范化 | 全角与半角、兼容字符 |
| ② | Unicode 简单大小写折叠（CaseFolding 表的 C 与 S 两类） | 大小写 |
| ③ | 去掉全部空白字符（Unicode `White_Space`） | 首尾与中间的空白 |

不做字形之间的转换（如繁体与简体）：那要一份一个字对一个字的对照表，不少字的对应随词而定，表的来源与版本都要另外钉住。`keymatch@1` 只用 Unicode 自带、随版本固定的数据。

**第二步，比较**新键 a 与已有键 b。长度按折叠后的码点数算，取第一个成立的级别：

| 级别 | `match` | 成立条件 |
|---|---|---|
| 1 | `fold` | N(a) = N(b) |
| 2 | `affix` | N(a)、N(b) 之一是另一个的前缀或后缀，且较短的一个不少于 2 个码点 |
| 3 | `edit` | 较短的一个不少于 3 个码点，且两者的编辑距离 ≤ 1；较短的一个不少于 8 个码点时放宽到 ≤ 2（初值） |

- **编辑距离**是按码点算的 Levenshtein 距离：插入、删除、替换各计 1，**不含换位**（相邻两个码点对调计 2）。含换位的距离有两种互不相同的定义，在阈值 2 上会对同一对键给出不同的答案；不含换位的只有一种读法，各实现结果一定相同。代价是短键上对调两个字不会被标出。
- **`edit` 要求至少 3 个码点**：两个字的中文键差一个字太常见（"房租"与"房贷"），标出来多半是误报。
- **多字段的键**：非 `text` 的键字段必须同值（按「同值判据」）；`text` 键字段逐个比较，每个要么原样相同，要么在某一级成立，且至少有一个不是原样相同。整个键的级别取各字段里最宽的一级。键里没有 `text` 字段的表不给 `similar_keys`。
- **比较范围**：该表本次调用可见的全部实体，含已撤销的（撤销之后实体与键仍在），已撤销的在结果里标 `revoked`。实体超过 5,000 个时只比最近写入的 5,000 个（初值）。
- **排序**：先按级别（`fold`、`affix`、`edit`），同级按编辑距离，再按最近写入，最后按实体 ID；取前 5 个。

**测试向量**（各实现都要通过）：

| 新键 a | 已有键 b | 编辑距离 | 结果 | 说明 |
|---|---|---|---|---|
| `q4 推广` | `Q4推广` | — | `fold` | 大小写与空白 |
| `ＡＢＣ部` | `abc部` | — | `fold` | 全角经 NFKC 变半角，再折叠大小写 |
| `STRAẞE` | `straße` | — | `fold` | U+1E9E 经简单折叠成 U+00DF。折叠的结果不一定仍是 NFKC 形式，判据按码点比较，不再规范化一次 |
| `Q4推广预算` | `Q4推广` | — | `affix` | 后者是前者的前缀 |
| `marketting` | `marketing` | 1 | `edit` | 多一个字母 |
| `marketnig` | `marketing` | 2 | `edit` | 换位计 2；较短的一个 9 个码点，阈值是 2 |
| `abdc` | `abcd` | 2 | 不相近 | 换位计 2；较短的一个 4 个码点，阈值是 1 |
| `CA` | `ABC` | 3 | 不相近 | 距离函数本身的向量（不受限的 Damerau–Levenshtein 会给出 2）；较短的一个不足 3 个码点，本来也不进 `edit` |
| `房贷` | `房租` | 1 | 不相近 | 不足 3 个码点 |
| `推廣` | `推广` | 1 | 不相近 | 不做字形转换；不足 3 个码点 |

报错里 `unknown_table` / `unknown_field` 的 `nearest` 判断"别名与请求里的名字是否相同"时，用的也是这里的折叠 N（见「schema 文档格式」的别名一条）。

## 精度与舍入

`quantity` 与 `decimal` 字段各有一个精度，写进编译后的定义。

| 键 | 取值 | 没声明时 |
|---|---|---|
| `scale` | 小数位数，0–12 | 货币取 ISO 4217 的最小单位位数（CNY 2、JPY 0、KWD 3）；其余取 6 |
| `rounding` | `half_up`（四舍五入，恰在一半时远离零）/ `half_even`（恰在一半时取偶） | `half_up` |

- **写入时**：值先换算到字段声明的单位，再按精度舍入后落账。小数位数超过 `scale` 而被舍入时，回执 `warnings` 给 `rounded`；调用方交来的原始值留在逻辑写入头里。例外：换算过单位的值只给 `unit_converted`（附换算并舍入后的值），不另给 `rounded`——换算后的精确值未必是有限小数，没有能写进 `rounded` 的原值。
- **用舍入后的值做的事**：同值判断、`min` / `max` 校验、疑似重复、冲突判定里"值是否不同"。
- **用原始值做的事**：字面命中（证据里写的是原始的数与单位）。
- **派生字段的精度**由编译器推断并回填，推不出时要求在该字段上写明 `scale`。推断按表达式逐层进行，任何一层的某个输入推不出，这一层就推不出：
  - 字段取它声明的精度；`integer` 与整数字面量的 `scale` 是 0，小数字面量取它写出的小数位数。
  - `sum` / `min` / `max` 沿用输入的；`avg` 取输入的 `scale` 与 6 的较大者；`count` 是整数。
  - 加、减、取模取两边的较大者；乘法取两边之和，超过 12 时取 12；除法取两边与 6 三者中最大的。
  - `round(x, n)` / `trunc(x, n)` 的 `n` 是整数常量时取 `n`（小于 0 取 0，大于 12 取 12），只给 `x` 时取 0；`n` 不是常量时推不出。`floor`、`ceil`、`sign`、`EXTRACT` 取 0；`abs` 与一元负号沿用参数的。
  - `CASE` / `COALESCE` / `GREATEST` / `LEAST` 取各分支的最大者，`NULL` 分支不参与。
  - 转换成 `numeric(p, s)` 取 `s`；`s` 至多 12，大于 12 的转换不收。
  - 舍入方式沿用各输入共同的那一种；输入的舍入方式不同或都没有时，取字段上写的 `rounding`，没写取 `half_up`。
  - 推得出时，字段上写的 `scale` / `rounding` 须与推断一致，否则报 `rule_sql_rejected`。
- 默认取 `half_up`，是因为它与 PostgreSQL `round(numeric, n)` 一致（`numeric` 在恰好一半时远离零舍入）：派生规则里写的 `round()` 与内核的舍入是同一种，两个后端不必另写实现。
- `half_even` 在 PostgreSQL 里没有针对 `numeric` 的内置函数（取偶舍入只是浮点类型的常见行为，且随平台而定），要由内核自己实现一个确定的版本，两个后端共用，并纳入重放一致性的实验（见 scope「必做的实验」实验 5）。
- 货币的默认 `scale` 取自 ISO 4217 的现行表。实现时由这张表生成，不手抄；表有变化时出新的单位词表版本。

## 单位词表

**词表是一份固定清单（`units@1`），不做单位表达式的运算。** 每个单位有：代码、量纲、换算到该量纲基准单位的系数。`units@1` 指事件格式 v1 冻结时这张表的内容；冻结之后改表就是出新的词表版本。

- **代码**：ASCII，区分大小写。公制单位与 UCUM 的写法相同；英制用常见缩写，另列 UCUM 代码供对外互操作。
- **同量纲** = 量纲标识相同。同量纲的单位自动换算：值 × 源单位的系数 ÷ 目标单位的系数，再按字段精度舍入。
- 系数是精确的十进制数，写成字符串。

| 量纲 | 基准 | 单位：代码（系数） |
|---|---|---|
| `length` 长度 | 米 | `mm`（0.001）、`cm`（0.01）、`m`（1）、`km`（1000）、`in`（0.0254）、`ft`（0.3048）、`yd`（0.9144）、`mi`（1609.344） |
| `mass` 质量 | 克 | `ug`（0.000001）、`mg`（0.001）、`g`（1）、`kg`（1000）、`oz`（28.349523125）、`lb`（453.59237） |
| `duration` 时长 | 秒 | `ms`（0.001）、`s`（1）、`min`（60）、`h`（3600）、`d`（86400）、`wk`（604800） |
| `volume` 体积 | 升 | `mL`（0.001）、`L`（1）、`floz`（0.0295735295625，美制液量盎司） |
| `energy` 能量 | 焦 | `J`（1）、`kJ`（1000）、`cal`（4.184）、`kcal`（4184） |
| `frequency` 频率 | 每天 | `/d`（1）、`/h`（24）、`/min`（1440）、`/s`（86400） |
| `speed` 速度 | 千米每小时 | `km/h`（1）、`m/s`（3.6）、`mi/h`（1.609344） |
| `dimensionless` 无量纲 | 1 | `1`（1，计数或比值）、`%`（0.01） |
| `temperature:<代码>` 温度 | — | `Cel`、`degF`、`K`：**各自成一个量纲，第一版不互相换算** |
| `currency:<代码>` 货币 | — | ISO 4217 现行的三字母代码（`CNY`、`USD`、`EUR`…）：**每种货币自成一个量纲，互不换算** |

- **基准单位的选法**只有一个要求：让每个系数都是有限小数。所以频率以"每天"、速度以"千米每小时"为基准；基准不对外，只用于换算。
- **月、年不收**：它们不是固定长度。
- **货币**：写入单位与字段声明的货币不同，报 `validation_failed`（`unit_dimension`）。要换算就把汇率作为基础数据接入、在派生规则里算（见「派生规则」）。
- **温度**：摄氏度与华氏度之间的换算带偏移，一个系数表达不了。第一版声明了哪个单位就只收哪个单位；互相换算后续再加，届时给单位定义新增一个可选的偏移量，已有定义不变。
- **英制代码对应的 UCUM 写法**：`in` = `[in_i]`、`ft` = `[ft_i]`、`yd` = `[yd_i]`、`mi` = `[mi_i]`、`oz` = `[oz_av]`、`lb` = `[lb_av]`、`floz` = `[foz_us]`、`degF` = `[degF]`、`mi/h` = `[mi_i]/h`。`ug` 与 UCUM 的 ASCII 写法相同（"微"的前缀写 `u`）。代码不含空白：`floz` 是 `fl oz` 去掉空格。
- **系数的出处**：国际码 = 0.9144 m、国际磅 = 0.45359237 kg 是 1959 年的国际协定值；英尺、英寸、英里、盎司由它们按整数比得出（1 mi = 5280 ft，1 lb = 16 oz）；`cal` 取热化学卡，恰为 4.184 J。美制加仑定义为 231 立方英寸，所以 1 加仑 = 3.785411784 L；液量盎司是加仑的 1/128，恰为 29.5735295625 mL。
- **词表外的单位**：草稿里用了报 `validation_failed`（`unit_unknown`），附同类候选；写入时单位不在词表报 `unit_unknown`，量纲与字段不同报 `unit_dimension`。确实没有合适单位的量，用 `decimal` 或 `integer` 字段，在说明里写清单位。
- **只收能精确定义、各地含义一致的单位**，词表里的每一行都是"saveslot 保证换算正确"的承诺：

  | 不收 | 为什么 | 替代做法 |
  |---|---|---|
  | 英制液量盎司 | 与美制差 4%，用户说"盎司"绝大多数指美制 | 按英制记的字段用 `mL` |
  | 杯、汤匙、茶匙 | 同一个词在各地是不同的量（杯有约 236.6、240、250、200 mL 几种，汤匙有约 14.8、15、20 mL），收进词表等于替用户选了一种，换算出的数悄悄差到两成以上 | 字段声明为 `mL`，Agent 换算后写入，用户原话（"两杯"）留在证据里；或用 `decimal` 字段，在说明里写"杯（本表按 240 mL）" |
  | 国际单位 IU | 不是固定的量，每种物质的换算不同，不能归入质量 | `decimal` 字段，说明里写"IU" |
  | 品脱、夸脱、加仑 | 日常记录里少见，同样有美制、英制之分 | `floz` 或 `L` |
  | `dL`、`cL` | 只是换一个前缀，换成 `mL` 不会错 | `mL` |
  | 份、个、片 | 不是物理单位 | 无量纲 `1`，字段说明里写清一份是多少 |
  | 浓度（`mg/dL`、`mmol/L`） | 词表没有浓度量纲，要先定量纲再收 | `decimal` 字段，说明里写单位 |

- 美国食品标签把 1 液量盎司按 30 mL 计，是标签的取整约定，不是单位定义；词表取定义值。按标签抄数的字段写 `mL` 更不容易出偏差。
- **派生字段的单位**由编译器推断（`sum` / `avg` / `min` / `max`、乘除常数）；两个带单位的字段相乘、相除得不出词表里的单位时报错，要求把结果声明成 `decimal` 并写明说明，或在该字段写明 `unit`。

## 单位同义表（字面命中用）

字面命中（见「来源级别」）要判断"证据原文里有没有这个数加这个单位"。单位在原文里有很多写法，下表是 `units@1` 认可的写法（同样指事件格式 v1 冻结时的内容）；它随核对器版本走（`literal@1` 含 `units@1`），改这张表就是出新的核对器版本，旧事件里记下的命中结果不变。

- 拉丁字母的写法不分大小写。
- 货币符号可以写在数字**前面**（`¥45`、`$12.5`）；其余写法在数字**后面**，中间可以隔空白。
- 单位 `1` 不要求单位写法，数字命中即可。

| 代码 | 认可的写法 |
|---|---|
| `CNY` | 元、块、块钱、圆、人民币、RMB、CNY、¥、￥ |
| `USD` | 美元、美金、USD、dollar(s)、$ |
| `EUR` | 欧元、EUR、euro(s)、€ |
| `JPY` | 日元、円、JPY、yen |
| `HKD` | 港币、港元、HKD、HK$ |
| `GBP` | 英镑、GBP、pound(s)、£ |
| 其他货币 | 只认 ISO 代码 |
| `km` | 公里、千米、km |
| `m` | 米、m、meter(s) |
| `cm`、`mm` | 厘米、公分、cm；毫米、mm |
| `mi`、`ft`、`in`、`yd` | 英里、mile(s)、mi；英尺、foot、feet、ft；英寸、inch(es)、in；码、yard(s)、yd |
| `kg`、`g`、`mg` | 公斤、千克、kg；克、g；毫克、mg |
| `ug` | 微克、µg、μg、ug、mcg |
| `lb`、`oz` | 磅、lb、lbs、pound(s)；盎司、oz |
| `h`、`min`、`s`、`ms` | 小时、钟头、h、hr(s)、hour(s)；分钟、分、min(s)、minute(s)；秒、秒钟、s、sec(s)；毫秒、ms |

- `GBP` 与 `lb` 都认 `pound(s)`，`floz` 与 `oz` 都认"盎司""oz"：字面命中只看字段声明的那个单位的写法，不会混。
