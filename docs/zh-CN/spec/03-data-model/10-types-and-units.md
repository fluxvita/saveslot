# saveslot · 数据层机制 · 10 字段类型、同值与单位

> 数据层机制的一部分，目录见 [`README.md`](README.md)。文中「…」引用的节可能在同目录的其他文件里，按目录查。

字段的类型怎么取值、两个值什么时候算"相同"、带单位的数怎么换算与舍入。这些规则被写入校验、同值判断、冲突判定、疑似重复与字面命中共用，所以集中在一处。

## 字段类型与取值范围

| 类型 | 是什么 | 取值范围 |
|---|---|---|
| `text` | 文本 | 至多 8 KB（UTF-8）。落账前做 Unicode NFC 规范化；首尾空白、大小写原样保留。空字符串是一个值，不是空 |
| `integer` | 整数 | 64 位有符号 |
| `decimal` | 小数 | 整数部分至多 18 位；小数位数 `scale` 0–12 |
| `quantity` | 带单位的数 | 数值同 `decimal`；单位取自「单位词表」 |
| `boolean` | 布尔 | — |
| `enum` | 枚举 | 至多 200 个取值，每个至多 64 个字符；区分大小写 |
| `date` | 日历日 | 0001-01-01 至 9999-12-31；按 slot 时区的自然日理解 |
| `zoned_datetime` | 时刻 + IANA 时区 | 毫秒精度 |
| `ref` | 指向同一 slot 另一张表的一行或一个实体 | 见「写入请求 · 引用字段」 |

- **名字**：slot 名、表名、字段名匹配 `[A-Za-z][A-Za-z0-9_]{0,62}`，在受限 SQL 里直接当标识符写。不得以 `_` 开头；字段名不得是 `valid`、`valid_from`、`valid_to`（这三个是写入与查询参数里的保留键）。违反时编译报 `validation_failed`（`reserved_name`）。
- **说明**（`description`）至多 500 个字符，内容不限。
- 数值在事件与存储里一律是十进制，不用浮点（见「派生规则 · 确定性边界」）。

## 清空字段

- 写入里把字段的值写成 `null`，是清空一个**可选**字段。它是一次**贡献**：值为空，值来源照常是这次写入的证据。
- **必填字段不能清空**：报 `validation_failed`（`required_missing`）。不想要这一行，用撤销。
- 删除重放时，空值贡献与其他贡献一样参与"最后一个仍在的贡献"：它的来源被删，更早的值回来（见「删除 · 重放规则」）。
- 新增时没带的可选字段没有贡献。新增时显式写 `null`，与"原来没有值"同值，按同值规则是无操作或佐证。
- 状态类表上，可选字段在一段区间上为空是"值为空"，不是无值区间；它的 值 ↔ 空 是取值变化，算挡点（见「时间 · 无值区间」）。
- 字面命中对空值记"不适用"。

## 同值判据

"与所见版本同值""值没变""疑似重复命中""按 `entity_key` 定位"用的都是这一张表。

| 字段类型 | 同值当且仅当 |
|---|---|
| `quantity` | 换算到字段声明的单位、按 `scale` 舍入后，数值相等（`1.0` 与 `1.00` 相同） |
| `decimal` | 按 `scale` 舍入后数值相等 |
| `integer` | 数值相等 |
| `text` | NFC 规范化之后逐码点相同。不去首尾空白，不折叠大小写 |
| `enum` | 取值相同 |
| `boolean` | 相同 |
| `date` | 同一天 |
| `zoned_datetime` | 同一瞬间**且**时区相同（时区不同，"哪一天"可能不同） |
| `ref` | 指向同一行或同一实体（请求里的临时名先解析成 ID 再比） |
| 空 | 空与空相同；空与任何值不同 |

状态类表上，"同值"另要求在解析出的整个区间上都相同（见「时间 · 用同样的值写」）。

## 精度与舍入

`quantity` 与 `decimal` 字段各有一个精度，写进编译后的定义。

| 键 | 取值 | 没声明时 |
|---|---|---|
| `scale` | 小数位数，0–12 | 货币取 ISO 4217 的最小单位位数（CNY 2、JPY 0、KWD 3）；其余取 6 |
| `rounding` | `half_up`（四舍五入，恰在一半时远离零）/ `half_even`（恰在一半时取偶） | `half_up` |

- **写入时**：值先换算到字段声明的单位，再按精度舍入后落账。小数位数超过 `scale` 而被舍入时，回执 `warnings` 给 `rounded`；调用方交来的原始值留在逻辑写入头里。
- **用舍入后的值做的事**：同值判断、`min` / `max` 校验、疑似重复、冲突判定里"值是否不同"。
- **用原始值做的事**：字面命中（证据里写的是原始的数与单位）。
- **派生字段的精度**由编译器推断并回填：`sum` / `min` / `max` 沿用输入字段的；`avg` 与除法取输入的 `scale` 与 6 的较大者；`count` 是整数。推不出时要求在该字段上写明。
- 默认取 `half_up`，是因为它与 PostgreSQL `round(numeric, n)` 一致（`numeric` 在恰好一半时远离零舍入）：派生规则里写的 `round()` 与内核的舍入是同一种，两个后端不必另写实现。
- `half_even` 在 PostgreSQL 里没有针对 `numeric` 的内置函数（取偶舍入只是浮点类型的常见行为，且随平台而定），要由内核自己实现一个确定的版本，两个后端共用，并纳入重放一致性的实验（见 scope「必做的实验」实验 5）。
- 货币的默认 `scale` 取自 ISO 4217 的现行表。实现时由这张表生成，不手抄；表有变化时出新的单位词表版本。

## 单位词表

**词表是一份固定清单（`units@1`），不做单位表达式的运算。** 每个单位有：代码、量纲、换算到该量纲基准单位的系数。

- **代码**：ASCII，区分大小写。公制单位与 UCUM 的写法相同；英制用常见缩写，另列 UCUM 代码供对外互操作。
- **同量纲** = 量纲标识相同。同量纲的单位自动换算：值 × 源单位的系数 ÷ 目标单位的系数，再按字段精度舍入。
- 系数是精确的十进制数，写成字符串。

| 量纲 | 基准 | 单位：代码（系数） |
|---|---|---|
| `length` 长度 | 米 | `mm`（0.001）、`cm`（0.01）、`m`（1）、`km`（1000）、`in`（0.0254）、`ft`（0.3048）、`yd`（0.9144）、`mi`（1609.344） |
| `mass` 质量 | 克 | `mg`（0.001）、`g`（1）、`kg`（1000）、`oz`（28.349523125）、`lb`（453.59237） |
| `duration` 时长 | 秒 | `ms`（0.001）、`s`（1）、`min`（60）、`h`（3600）、`d`（86400）、`wk`（604800） |
| `volume` 体积 | 升 | `mL`（0.001）、`L`（1） |
| `energy` 能量 | 焦 | `J`（1）、`kJ`（1000）、`cal`（4.184）、`kcal`（4184） |
| `frequency` 频率 | 每天 | `/d`（1）、`/h`（24）、`/min`（1440）、`/s`（86400） |
| `speed` 速度 | 千米每小时 | `km/h`（1）、`m/s`（3.6）、`mi/h`（1.609344） |
| `dimensionless` 无量纲 | 1 | `1`（1，计数或比值）、`%`（0.01） |
| `temperature:<代码>` 温度 | — | `Cel`、`degF`、`K`：**各自成一个量纲，第一版不互相换算** |
| `currency:<代码>` 货币 | — | ISO 4217 现行的三字母代码（`CNY`、`USD`、`EUR`…）：**每种货币自成一个量纲，互不换算** |

- **基准单位的选法**只有一个要求：让每个系数都是有限小数。所以频率以"每天"、速度以"千米每小时"为基准；基准不对外，只用于换算。
- **月、年不收**：它们不是固定长度。
- **货币**：写入单位与字段声明的货币不同，报 `validation_failed`（`unit_dimension`）。要换算就把汇率作为基础数据接入、在派生规则里算（见「派生规则」）。
- **温度**：摄氏度与华氏度之间的换算带偏移，一个系数表达不了。第一版声明了哪个单位就只收哪个单位；互相换算后续再加，届时给单位定义新增一个可选的偏移量，已有定义不变。
- **英制代码对应的 UCUM 写法**：`in` = `[in_i]`、`ft` = `[ft_i]`、`yd` = `[yd_i]`、`mi` = `[mi_i]`、`oz` = `[oz_av]`、`lb` = `[lb_av]`、`degF` = `[degF]`、`mi/h` = `[mi_i]/h`。
- **系数的出处**：国际码 = 0.9144 m、国际磅 = 0.45359237 kg 是 1959 年的国际协定值；英尺、英寸、英里、盎司由它们按整数比得出（1 mi = 5280 ft，1 lb = 16 oz）；`cal` 取热化学卡，恰为 4.184 J。
- **词表外的单位**：草稿里用了报 `validation_failed`（`unit_unknown`），附同类候选；写入时单位不在词表报 `unit_unknown`，量纲与字段不同报 `unit_dimension`。确实没有合适单位的量，用 `decimal` 或 `integer` 字段，在说明里写清单位。
- **派生字段的单位**由编译器推断（`sum` / `avg` / `min` / `max`、乘除常数）；两个带单位的字段相乘、相除得不出词表里的单位时报错，要求把结果声明成 `decimal` 并写明说明。

## 单位同义表（字面命中用）

字面命中（见「来源级别」）要判断"证据原文里有没有这个数加这个单位"。单位在原文里有很多写法，下表是 `units@1` 认可的写法；它随核对器版本走（`literal@1` 含 `units@1`），改这张表就是出新的核对器版本，旧事件里记下的命中结果不变。

- 拉丁字母的写法不分大小写。
- 货币符号可以写在数字**前面**（`¥45`、`$12.5`）；其余写法在数字**后面**，中间可以隔空白。
- 单位 `1` 不要求单位写法，数字命中即可。

| 代码 | 认可的写法 |
|---|---|
| `CNY` | 元、块、块钱、圆、人民币、RMB、CNY、¥、￥ |
| `USD` | 美元、美金、USD、dollar(s)、$ |
| `EUR` | 欧元、EUR、euro(s)、€ |
| `JPY` | 日元、円、JPY、yen |
| `HKD` | 港币、港元、HKD、HK$ |
| `GBP` | 英镑、GBP、pound(s)、£ |
| 其他货币 | 只认 ISO 代码 |
| `km` | 公里、千米、km |
| `m` | 米、m、meter(s) |
| `cm`、`mm` | 厘米、公分、cm；毫米、mm |
| `mi`、`ft`、`in`、`yd` | 英里、mile(s)、mi；英尺、foot、feet、ft；英寸、inch(es)、in；码、yard(s)、yd |
| `kg`、`g`、`mg` | 公斤、千克、kg；克、g；毫克、mg |
| `lb`、`oz` | 磅、lb、lbs、pound(s)；盎司、oz |
| `h`、`min`、`s`、`ms` | 小时、钟头、h、hr(s)、hour(s)；分钟、分、min(s)、minute(s)；秒、秒钟、s、sec(s)；毫秒、ms |
| `d`、`wk` | 天、日、d、day(s)；周、星期、礼拜、wk、week(s) |
| `L`、`mL` | 升、L；毫升、mL |
| `kcal`、`cal`、`kJ`、`J` | 千卡、大卡、kcal；卡、cal；千焦、kJ；焦、焦耳、J |
| `/min`、`/s`、`/h`、`/d` | 次/分、次/分钟、每分钟、bpm、/min；每秒、/s；每小时、/h；每天、/d |
| `km/h`、`m/s`、`mi/h` | 公里/小时、公里每小时、km/h、kph；米/秒、米每秒、m/s；英里/小时、mph、mi/h |
| `%` | %、％、percent |
| `Cel`、`degF`、`K` | 度、摄氏度、℃、°C；华氏度、℉、°F；开、K |

- "斤""两""亩"这类不在词表里的单位不收：它们的数值与词表里的单位不同，算命中会是错的。
- `GBP` 与 `lb` 都认 `pound(s)`：字面命中只看字段声明的那个单位的写法，不会混。
