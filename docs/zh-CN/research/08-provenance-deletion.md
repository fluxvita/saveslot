## 0. 结论先行

1. **部分采纳：采纳"参考语义 + 两条分类原则 + 一组对照测试"，不采纳"给每个值存来源多项式"。**
   来源半环只覆盖**单调**的部分（"还有没有来源"：佐证 = 或、联合推导 = 且）；saveslot 的删除本质上**不单调**——删掉后面的写入，前面的值会**回来**（纠错被删、相邻段恢复、`next_change` 重新延伸）。
   这部分半环表达不了，只能靠重放。所以理论给 saveslot 的不是新的存储结构，而是：**删除结果的标准定义**（"当这些源数据从未存在过时，重放日志会得到什么"——即 DRed / 重演 reenactment 的做法）和一个**可执行的参考求值器**。
2. **saveslot 现有的"去掉贡献、再重放"本身就是这条标准的做法**（DRed 的"先删再重新推导"、GProM 的"按审计日志重演"），方向是对的。问题出在重放规则里几条**按"写入当时的判定照用"**写死的地方：它们让结果偏离"从未存在过"。
3. **理论给出两条分类原则，可以替换多条手工占位**：
   - **只追数据依赖，不追控制依赖**：值从哪来（证据、`api_call`、被回退 / 被采纳的那个值的来源）算值来源；谁触发、谁决定（回退请求、撤销的证据、解决请求、`acknowledge`）不算。人的决定**照记录执行**，不重做。
   - **saveslot 自己的确定性判定，一律按删除后的输入重算**：同值判断、`next_change` 解析、`ver` 冲突、系统裁定、高影响判断、行的存在。现行规则只重算了前两项（`next_change` 还只重算了一半）。
4. **按参考语义逐条对比，现有规则有 5 处结果不同**（§3.2）：行的存在用"接替为插入"（推演 3 的 Q41 已发现）；**冲突的成因被删后候选仍挂着**（新发现，r11 例）；**`next_change` 只在"挡点被删"时才重新解析，范围太窄**（新发现）；状态类表写入的区间参数没有自己的来源（新发现）；翻译结果只按"该字段的贡献"清除、漏了模型实际看过的其他原文（新发现）。另有 Q40（回退）、Q43、Q49、Q51 四处现行占位与理论不符，理论都能直接给出答案。
5. **实现代价很小**：不加新表。现有的 `base_sources`（字段 × 证据，分值 / 操作）+ change_log 顺序**就是**来源表达式（"按 `seq` 的决策表"）；唯一要改的存储是：回退 / 采纳 / 系统裁定的值来源从"拷贝一份源数据 ID 列表"改成**引用被搬运的那几个贡献**（写入 `seq` + 字段 + 区间），否则"或 / 且"结构会丢。计算量与现在的重放相同：受影响行 / 实体的历史长度 + 受影响分区的重算。
6. **最大的收益是测试**：参考求值器是日志与"删除集合"的纯函数，可以当 `delete` 的对照（oracle）。由此得到一组性质测试：删除结果 = 参考求值器结果；删除顺序无关；删除再撤回 = 从未删除；任何留下的值都不依赖被删源数据（隐私不变量）；没有来源被删的值不变（不多删）。推演 3 的每个例子都能写成一条用例。
7. **对外标准**：W3C PROV-DM / PROV-O 可以做来源的**导出与审计格式**（值来源 → `wasDerivedFrom` / `hadPrimarySource`，操作来源 → `qualifiedAssociation` + `hadPlan`，删除 → `wasInvalidatedBy`），但它不定义删除语义、不区分"或 / 且"，**不进第一版**，只作将来导出格式的候选。

## 2. 用来源表达式写 saveslot 的删除规则

### 2.1 记号与参考语义

| 记号 | 含义 |
|---|---|
| `s`（源数据 ID） | 布尔变量。隐私删除（含宽限期内）= 取 false；其余 = true。所有被删源数据合起来是一个赋值 ν |
| `+`（或） | 佐证：几条**独立**来源，任一条在就够 |
| `·`（且） | 联合推导：几条来源**同时**在才成立 |
| `c(w, f)` | 写入 w 对字段 f 的贡献的存在条件 = w 给 f 引用的证据之积（没给映射 = 这次写入全部证据之积） |
| `1` | 不是用户内容的常量（schema 事件、常量 `backfill`）：永远为真 |

**参考语义（删除结果的标准定义）**：`Eval(日志, ν)` = 按 `seq` 重放全部写入，其中

1. 每个贡献 `c(w, f)` 在 ν 下为假就去掉（**数据依赖**）。
2. **人的决定照记录**：撤销、回退、采纳候选 / 回到冲突前、确认、拒绝、`acknowledge`——不重做，也不因其操作来源被删而撤销（**控制依赖不追**）。它们搬运的值，存在条件 = 被搬运的那个贡献的存在条件。
3. **saveslot 自己的确定性判定按重放出的状态重算**：同值判断、`next_change` 终点、`ver` 冲突、系统裁定、高影响判断、行 / 实体的存在。
4. 派生 = 规则在结果上重算；由内容算出的内容（请求键、翻译、事项条目、分组键映射、结果校验和）按各自的表达式保留或清除。

这正是"假如被删的源数据从未存在过，saveslot 会得出什么"（反事实），只在第 2 条上有意偏离：人当时基于看到的内容做的决定，反事实里无从得知，只能照记录。

**为什么不能只用半环**：字段的当前值是"**按 `seq` 最后一个仍在的贡献**"——值 = v_k 当且仅当 `c(w_k, f)` 为真且所有更晚改过 f 的 `c(w_j, f)` 都为假。这里有"非"，是一张**决策表**，不是只含与、或的式子。删掉 w_j，w_k 的值回来——单调的半环表达不了"回来"。所以下表里"值"一列写的是决策表，"存在"一列才是半环式。

### 2.2 各类值的来源表达式

推演里的例子编号：推演 1 = R（`walkthrough-running`），推演 2 = B（`walkthrough-budget`），推演 3 = D（`walkthrough-deletion`）；data-model 自带的例子记 DM。

| 1 | **插入** w 给的字段 f | `c(w,f)` = w 给 f 的证据之积；只有一段证据时就是该变量，如 `R1` | 若 f 之后没有仍在的改动：`c(w,f)` 真 → 原值；假 → 字段无值 | DM runs#1 #41 |
| 2 | **普通更新** / **纠错**（两者在来源上没有区别，区别只在影响查询） | `c(w,f)`，如 `R3` | 决策表：f = 按 `seq` 最后一个仍在的贡献的值 | DM #57：删 R3 → distance 回到 15 |
| 3 | **同值佐证**（显式指向的同值写入 u） | 值 v 的支撑 = 原贡献 `+` `c(u,f)`，如 `R1 + R3` | 在决策表里，u 是 f 上一条值为 v 的条目；前面的条目被删时，u 就成了"真正给值" | DM #60；D 1b #202、#203；D 2a/2b #210 |
| 4 | **回退**到版本 t（字段 f，状态类表另带区间） | **搬运**：在每个点上 = t 时刻该点生效的那个（或那几个同值佐证的）贡献之和，如 `s_b2`；回退请求 `s_b6` 是操作来源，不进式子 | 被搬运的贡献仍在 → 回退的值保留；全部不在 → 回退在该点**没有贡献**，决策表落到回退之前的值（**不是**置空，也**不是**按删除后的历史重新取 t 时刻的值）| D 3a #111；B 第 4 步 |

| 8 | **一个字段引用多段证据**（含不给映射、默认全部） | **积**：`s_7 · s_8` | 任一段被删，这次写入对该字段的贡献去掉 | D 1c r3 |

| 10 | **确定性转换**（`migrate`、换时区后的日期）/ 单位换算 | 输入字段贡献之积 / 与原贡献相同 | 同 #1、#2 | data-model「换算、迁移」表 |

| 15 | 派生写入的结果校验和 | 读集里全部基础版本之积 | 读集里任一贡献被去掉就清除 | D 1a |
| 16 | 请求键、逻辑写入头参数 | 这次写入**全部证据**之积 | 任一段证据被删即清除 | R Q1 |
| 17 | **状态类表的段**（实体 e，业务时间点 t） | 点 t 上的值 = 决策表：按 `seq` 最后一个"仍在、且（重新）解析出的区间覆盖 t"的写入的值。段 = 值相同的连续点；**段的端点不需要单独的来源**，由各写入的区间与存在条件推出 | 被删写入切出的段消失，被盖住的更早写入重新可见 | DM 推广预算；D 3a、3b |
| 18 | 区间起点、显式终点 | 与这次写入的值同一个存在条件；**多段证据时按 #16 取全部证据之积**（区间是用户说的内容） | 同 #17 | — |
| 19 | 由 `next_change` 解析出的终点 | 函数：在**删除后**、本写入之前的状态上，起点之后的第一个变化点（取值变化处）。相当于"候选变化点按业务时间排序，取第一个仍成立的" | 每次删除重放都重新解析（不只挡点被删时） | DM s_R2 例；§3.2 N2 |
| 20 | **行是否存在**（事件类表、无时间表） | ∏_{f ∈ 必填字段} ( Σ_{w} `c(w,f)` )——每个必填字段**至少有一个仍在的贡献** | 存在 → 各字段取决策表结果；不存在 → 整行删除 | D 1a、1b；R 第 7 步 |
| 21 | **实体在业务时间点 t 是否有值**（状态类表） | 键字段（实体级）`Σ_w c(w, key)` **·** 点 t 上值字段有仍在的覆盖写入 | 按点（即按段）判断：有值的段保留，其余是空洞 | D 3c |
| 22 | 按 `entity_key` 定位的写入"给出键字段" | 定位用的键值是**这次请求带的值**，`c(w, key)` = 这次写入的证据 | 与普通给值相同 | D 3c #123 |
| 23 | 撤销一行 | 控制决定，不进式子；撤销的证据是操作来源 | 照记录生效；撤销的证据被删不让行复活 | D 2d |
| 24 | 冲突事项 / 待确认事项（未决） | 事项存在 = 候选（提议）值的存在条件 · 冲突（高影响）成因的存在条件 | 任一为假 → 事项"已被取代"（候选按 #6、#7 处理） | D 2c、4c |
| 25 | 删除证据的"被引用"判断 | 另一种赋值 ν_text：**原文已删**（含删除证据）的都取 false；看当前值的支撑在 ν_text 下是否仍为真 | 为假 → 拒绝（`referenced`） | D 2a、2b、Q52 |

注：

- **字段值用 where、存在用 why**：#1–#11 是"值从哪来"，#12、#20–#22 是"这一行 / 组 / 段凭什么存在"。现行规则把两者揉在"插入它的写入还在、且仍给出全部必填字段"一句里，这是 §3.2 N0 的根源。
- **两个赋值**：隐私删除用 ν（被删源数据的贡献整体去掉）；删除证据只删原文，贡献仍在，所以"被引用"判断要用另一个 ν_text。两者分开，Q52 的三个问题就都有了答案（§3.3）。
- **"或"只能来自不同的写入**：同一次写入里多段证据按积处理（#8）。这是在不知道映射时唯一**不会少删**的选择：任何只含与、或、且在全真时为真的式子 φ，都有"全部为真 ⇒ φ 为真"，所以"全部都在才保留"是 φ 的下界——多删、但绝不漏删。

### 3.3 DRAFT 占位：理论能否直接给出答案

**「删除统一模型的细则」**

| 占位 | 理论给的答案 | 依据 |
|---|---|---|
| 1. 多段证据：任一段被删即去掉（还是强制字段映射） | **保留，作为默认**；不必强制映射。可选增强：允许按字段声明"任一即可"（`any_of`），表达 #3 那种"或"，省掉 D 1c 那样的二次佐证 | 积是唯一不漏删的默认（§2.2 注） |
| 2. 值来源的边界（`api_call` / `set` / 撤销证据） | 三项都按现占位 | 数据依赖 vs 控制依赖 |
| 3a. 接替为插入 vs 累积到给齐必填字段 | **按字段累积**（N0） | #20 |
| 3b. 按 `entity_key` 定位算不算给出键字段 | **算** | #22：定位用的键值就是这次请求带的值 |
| 3c.（推演 3 Q49②）实体存在按整个实体还是按段 | **按段（按业务时间点）** | #21 |
| 4. 回退目标在删除后没有值：去掉贡献还是置空 | **去掉贡献**，且"有值但已是别的值"同样去掉（Q40） | #4 |
| 5. 翻译清除后要不要重新补抽 | **要**（推演 3 Q50 的建议）：反事实结果 = 在剩余原文上重新抽取；模型不可重放，只能开补抽作业 | 删除 = 在剩余输入上重新推导；对不可重放的函数只能重算 |
| 6. 系统裁定是否触发纠错影响查询 | **理论不涉及**（这是读取影响，不是来源） | — |

**「第三轮修订的占位」**

| 占位 | 理论能否回答 |
|---|---|
| 删除让有未决冲突的字段级别变了：不重新裁定 | **能，答案是重算**（Q51）：冲突与系统裁定都是机械判定。推演 3 的 4c' 里被删的 #57 正是冲突的成因，按 #7 冲突直接消失、候选 20.5 生效；成因还在、只是级别变了时，按 #6 在删除后的级别上重新裁定。现行"重放不重做冲突判断"应收窄为"不重做**人的**决定" |
| 恢复出的存储早于仍在宽限期的删除 / 补删时被引用挡住 / 冷归档作废 / 请求键过窗口是否删 / 单位换算精度 | **不能**——都是运维、存储、法务口径，与来源语义无关 |

**推演 3 的 Q40–Q61 里与来源语义有关的**：

| # | 理论的结论 |
|---|---|
| Q40 | 支持建议（"去掉贡献"优先），见 §3.2 |
| Q41 | 支持建议（按字段累积），见 N0 |
| Q42 | 支持建议，并给出判据：**按行删除能否无副作用** = 这些行的来源变量集合 V，与其他行 / 值的来源变量集合**不相交**。相交（如 `s_10` 被三行共用）就只能把变量切细（按 op 拆 `api_call`）。saveslot 的来源是显式记下的，这个判断是多项式的集合运算，没有 Buneman 2002 里的 NP-hard |
| Q43 | 支持建议，并且是 N1 原则的特例：#24 候选的存在条件为假 → 事项已被取代 |
| Q44 | 语义上映射是"和"（#14），所以它**不能只存在于某一次派生写入的内容里**——那份内容会随一个加数被删。支持"在新派生写入里重新登记"的建议 |

| Q51 | 支持建议（重新裁定），见上 |
| Q52 | 给出统一答案：两个赋值 ν / ν_text（#25）。`referenced` 只看 ν_text；隐私删除时删除证据过的来源仍为真；级别沿用写入时记下的核对结果 |
| Q54 | 理论给了另一种选择——"历史 = 在日志前缀上求 Eval"（反事实历史，不会出现缺必填字段的历史行），但它会改写版本表的区间，审计与 read_log 引用的版本会对不上。**建议维持现状（历史只去内容、标 `partially_deleted`）**，并写明：参考语义只约束**日志末端**的状态 |
| Q56 | 原则 3 的特例：撤回时冲突、高影响都按重放状态重算，宽限期内改过该字段的，事项自然是"已被取代" |
| Q46、Q47、Q53、Q55、Q57–Q61 | 理论不涉及（编号、登记、幂等、错误码、读取标记、归档、导出） |

### 3.4 一个未被推演覆盖、建议补推的点

**待确认（高影响）写入的成因被删**：一次 `valid_to: open` 的写入因为会抹掉 11-10 这个变化点而进了待确认；之后删掉建立 11-10 那段的源数据。按原则 3，高影响判断在删除后的状态上重算——它已不覆盖任何已知事实，应按普通写入生效，事项"已被取代"。这与 N1 是同一原则，但会让一个"Agent 被告知未生效"的写入悄悄生效，**产品上需要确认**；建议在下一轮删除推演里加一步。

## 4. 实现代价

### 4.1 每处要存什么

| 位置 | 理论上的表达式 | 实际存什么 | 相比现在 |
|---|---|---|---|
| 基础写入 × 字段 | `c(w,f)`（证据之积） | `base_sources`：写入 → 源数据，带字段列表与种类（值 / 操作）——**就是积的各项** | 不变 |
| 字段当前值 | 决策表 | change_log 里该行 / 实体的写入顺序 | 不变 |
| 同值佐证 | 和 | 同值写入事件里"字段 → 未变、追加的来源" | 不变 |
| 回退、采纳候选、系统裁定的值来源 | 被搬运的贡献的存在条件（可能是"和"） | **改**：存"引用了哪几个贡献"——（写入 `seq`，字段，状态类表另带区间）——而不是把源数据 ID 拍平成一个列表。拍平后分不出"和"与"积"：被搬运的值若由两次写入同值佐证，拍平成积会多删，拍平成和又可能漏删 | 小改（来源表加一种"引用贡献"的行） |
| 冲突 / 待确认事项 | #24 | 事件里已有 `ver`、候选、被覆盖的段；成因由重放现算 | 不变 |
| `next_change` 终点 | 函数 | 原始传参（已记）；挡点来自哪次写入可以不再需要（总是重新解析） | 不变或更少 |
| 状态类表区间参数 | 积，或映射 | 证据映射加一个 `valid` 键（N3） | 小改 |
| 翻译结果 | 原文之积 | 工作项的来源簇（已有） | 不变（N4 只改清除条件或改附带范围） |
| 派生分区 | 和（存在）、半模（值） | `derived_reads` 分区级读集（已有）；值靠重算 | 不变 |
| PosBool 最小见证 | — | **不存**。saveslot 的式子是"每字段若干个积的和"，最小见证就是 `base_sources` 本身；预存只在"不重放就要秒出预览"时才有用，而重放已经足够快 | — |

### 4.2 量级与最坏情况

| 项 | 量级 | 说明 |
|---|---|---|
| 一个字段的表达式大小 | 改过它的写入数 × 每次的证据段数 | 典型 < 10 × 1–3；与 `base_sources` 行数相同，不膨胀 |
| 一次删除的计算 | Σ_{受影响行 / 实体} 历史长度 + 受影响分区的重算 | 与现行统一模型相同；分区重算按 02 报告实测约 1.7 ms / 分区 |
| **表达式膨胀**（理论上的最坏情况） | 连接 / 嵌套派生会让"积的和"按乘法展开，指数增长 | saveslot 用三条把它挡在外面：① 派生不存式子、只重算；② 回退 / 采纳存**引用**而不是展开，链式回退是一条引用链，长度不超过历史；③ 同一写入内一律按积，不出现"和的积" |
| 共享源数据（一个导入文件 → 上千行） | 受影响行数 × 每行历史 | 线性。与现在一样，是"一条源数据被很多行共用"本身的代价；Q42 的"按 op 切源数据"能把它变小 |
| 长历史的状态实体（上千段） | 按点 / 按段重放，O(写入数 × 段数) | 可以只重放受影响的业务时间范围之后的部分；第一版不必优化 |

### 4.3 与"日志是唯一事实来源 / `apply` / 重放"怎么衔接

- **`Eval` 是日志的纯函数**：输入 = 日志里的写入事件 + 日志里的删除事件（已确认、未撤回的隐私删除给出 ν；删除证据给出 ν_text）。所以删除后的状态在原理上可以从日志算出，K12 不受影响。
- **但不能让 `apply` 去算它**：内核版本升级可能改 `Eval` 的细节，重放旧日志时结果会变。现行"`delete` 算好写进删除已确认事件，`apply` 照做"仍然是对的——事件里的结果是 `Eval` 在**当时内核版本**下的缓存。
- **由此多出一项对账**：同一内核版本下，"删除已确认 / 撤回事件里记下的结果"应等于"`Eval` 在该事件处的重算结果"。这能抓住 `delete` 的实现错误，而现在的"从空存储重放 = 线上状态"抓不到（重放用的就是事件里写好的结果）。
- **撤回**：ν 里把对应变量改回 true，重算——与现行"同一套重放"一致；宽限期内的新写入照常进决策表，它们的冲突 / 高影响按原则 3 重算（Q56 自动成立）。
- **到期物理删除**不改 ν（变量在确认时就已是 false），只删内容——与现行一致。
- **按时刻读**：参考语义只定义日志末端的状态；历史版本照现行"只去内容"（§3.3 Q54）。

## 5. 结论与建议

### 5.1 采纳到什么程度

| 部分 | 采纳？ | 理由 |
|---|---|---|
| 参考语义（反事实重放，人的决定照记录） | **采纳**，写进 data-model 作为删除结果的定义 | 一句话定义替代多条手工规则；可执行、可测 |
| 原则：只追数据依赖、不追控制依赖 | **采纳** | 直接回答占位 2、Q40，解释"操作来源不挡"为什么成立 |
| 原则：saveslot 的确定性判定按删除后的输入重算 | **采纳** | 直接回答 Q43、Q51、N1、N2、Q56；替换"重放不重做冲突判断"那一行 |
| 同一写入内多段证据按积、不同写入之间按和 | **采纳**（就是现行规则） | 理论证明它是唯一不漏删的默认 |
| 行存在 = 每个必填字段至少一个仍在的贡献 | **采纳**（N0 / Q41） | 去掉"接替为插入"这条手工规则 |
| 给每个值预存来源多项式 / PosBool 最小见证 | **不采纳** | 覆盖写入不单调，式子算不出删除后的值；`base_sources` + 日志顺序已是全部信息 |
| ProvSQL 一类行级来源引擎 | **不采纳** | 02 报告已排除（不进 WAL、不随事务） |
| W3C PROV 作导出格式 | **不进第一版**，记为将来审计导出的候选 | 不定义删除语义、不区分或 / 且，对内核无收益 |
| 参考求值器作测试对照 | **采纳**，第一版就做 | 收益最大、成本最小 |

### 5.2 data-model「删除」一节建议改成的样子（要点，未改文档）

1. **开头加"删除结果的定义"**：隐私删除后的状态 = 假如被删源数据从未存在过，按 `seq` 重放日志得到的状态；人的决定（撤销、回退、采纳 / 回到冲突前、确认、拒绝、`acknowledge`）照记录执行。`delete` 按此计算，撤回同理。
2. **「来源：值来源与操作来源」**：保留两分法，补一句"值来源 = 数据依赖，操作来源 = 控制依赖；删除只追数据依赖"。补三条：
   - 同一次写入里一个字段引用多段证据 = 同时需要（积）；可选 `any_of` 表示任一即可。占位标为已定。
   - 回退、采纳候选、系统裁定的值来源**存为对被搬运贡献的引用**（写入、字段、区间），不拍平成源数据列表。
   - 状态类表的区间参数是内容：可按 `valid` 映射证据，不映射 = 全部证据之积（N3）。
3. **「重放规则」表**改四行：
   - "不重做" → **只有人的决定不重做**；`ver` 冲突、系统裁定、高影响判断、同值判断、`next_change` 都在删除后的状态上重算（冲突成因全被删 → 候选按普通写入在自己的 `seq` 生效、事项已被取代；级别变了 → 重新裁定）。
   - "参数" → 解析结果照用，**`next_change` 终点一律重新解析**（N2）。
   - "回退" → 被搬运的贡献都不在时，回退在该处没有贡献，落回回退前的值；不按删除后的历史重新取目标（Q40）。
   - "行 / 实体的存在" → 每个必填字段至少有一个仍在的贡献；状态类表按业务时间点（段）判断；`entity_key` 定位算给出键字段。删去"接替为插入""残余不再适用"（N0、Q49）。
4. **「由源数据派生出的内容」表**：翻译结果的清除条件改为"工作项附带的任一原文被删"（或工作项只附相关证据）（N4）；写入头参数改为"它自己的来源被删时清除"（N3）；分组键映射注明"任一行仍带此键即保留，宽限期内重新出现时在新的派生写入里重新登记"（Q44）。
5. **删除证据**：注明"被引用"判断看的是"原文仍在的来源"，删除证据过的来源对隐私删除仍算在（Q52）。
6. **"由此得出的推论"一段**改写成"参考语义下的推论"，并加一条：**删除只会让冲突、待确认消失，不会产生新的冲突**（夹在中间的改动只会变少）——这是可测的性质。
7. DRAFT「删除统一模型的细则」1–5 按 §3.3 标为已定；6 留给读取影响那一侧；第三轮占位里"级别变了不重新裁定"改为"重新裁定"。

### 5.3 作为删除推演与测试的对照标准

**参考求值器**（内核里的 `delete` 之外另写一份最直白的实现，只用于测试）：输入（某行 / 实体的写入事件、删除集合）→ 输出（字段值、存在、段、未决事项）。附录 A 的原型约 120 行，覆盖了事件类与状态类。

**性质测试**（每条都能说出"在什么输入下会失败"）：

| 性质 | 写法 | 抓什么错 |
|---|---|---|
| 与参考一致 | `delete(D)` 写进事件的结果 = `Eval(日志, ν_D)` | `delete` 的任何规则实现偏差（如 N0–N4） |
| 顺序无关 | 先删 A 再删 B = 先删 B 再删 A = 一次删 {A, B} | 结果依赖删除历史（如 D 3a/3b 叠加） |
| 撤回还原 | 删 A 再撤回 = 从未删 A（含宽限期内新写入） | 撤回漏放回的贡献、事项恢复错（Q56） |
| 隐私不变量 | 结果里每个值、段端点、事项条目、翻译、分组键，其表达式在 ν_D 下都为真 | 漏删（N3、N4 这类） |
| 不多删 | 某个值的表达式里不含被删变量，则它不变（同一实体内的段重排除外） | 宁可多删的规则用过了头 |
| 冲突只减不增 | 删除前没有的冲突 / 待确认，删除后也没有 | 重算判定的实现错误 |
| 记录与重算一致（对账） | 同一内核版本下，日志里删除事件的结果 = 在该处重算 `Eval` | 线上 `delete` 的缺陷（现有对拍抓不到） |

**推演的写法**：以后的删除推演每一步给出"参考语义的结果"一列，与"按文档规则推出的结果"并排；两列不同就是问题。推演 3 的例子都可以直接变成上面"与参考一致"的用例，附录 A 已有 12 个。

### 5.4 将来如果要对外（不进第一版）

PROV-O 映射草案：源数据 = `prov:Entity`（`hadPrimarySource`）；基础写入 = `prov:Activity`，`used` 证据、`wasAssociatedWith` 连接实例（`qualifiedAssociation` + `hadPlan` 可放操作来源）；行版本 = `prov:Entity`，`wasGeneratedBy` 写入、`wasRevisionOf` 上一版本；派生分区 `wasDerivedFrom` 读集；删除 = `wasInvalidatedBy` 删除活动。PROV 里表达不了"或 / 且"，导出时只能把 `+`、`·` 放进自定义属性，或用 `qualifiedDerivation` 的角色区分。被删内容在导出里只能出现为没有属性的不透明 ID。
