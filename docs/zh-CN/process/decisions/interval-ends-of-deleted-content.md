# 决定：按记录时刻读时，出自被删内容的区间端点不给出

> 不改事件格式，不改 K1–K14，不改存储格式。操作契约：按记录时刻读的结果里，一段的起点、终点在这种情形下可以缺；翻页位置在它发出之后有删除被确认或撤回时过期；状态类表翻页位置里的键多一个。

本文里「按记录时刻读」指 `history` 的 `as_of` 与 `changes`，以及 `query` 的后续页（它按第一页那一刻读）。「端点」指状态类表上一段的起点或终点。

## 要解决什么

隐私删除确认之后，按记录时刻读不再给出被删内容给出的**值**。但一段的**起止日期**也可能出自被删的内容，现在照旧给出。三种来路：

1. **被删的那句话自己说的日期。** 只删说明起止的那句话（区间的证据）时，它说的日期仍在 `as_of` 的结果里。
2. **别的写入的默认终点停在被删写入的变化点上。** #1 写 5000，10-01 起；#2 写 4000，11-20 起，之后被删；#3 写 3000，11-10 起，不传终点，默认终点停在 #2 的 11-20。删掉 #2 之后按 #3 那一刻读，仍是 `[11-10, 11-20) 3000`：11-20 是被删的写入说的日期。紧随其后那一段（值已经不给）的起点同样是它。
3. **`changes` 按被删写入内部的切点分段。** `as_of` 合掉的切点，在 `changes` 的区间里露出来。

规格现在两处说法相抵：03-deletion「版本表」一行说被删内容所在版本「区间保留」；「区间参数」说起点与显式终点是用户说的话，也就是内容。同一文件的例子（默认终点停在被删写入给出的变化点上）写的是「这一项显示为已删除，不显示旧的终点」。

`history` 的 `timeline` 不在其列：它给每一项最近一次给出的区间，被删除重新解析过的给新的那个；被删的那一项不给区间。它今天就不给出被删的日期。

## 决定

### 1. 端点由谁给出，按给出者判

一段的端点 P 由一项贡献的区间给出：

- 这一项自己的区间有一端正好是 P：P 由这一项给出。
- 否则 P 是被相邻的项切出来的：由相邻那一项的区间端点给出（右边那一项的起点，或左边那一项的终点；挨着的是撤销留下的空隙时，由那次撤销的区间给出）。
- 两边都有端点落在 P 上时，以这一项自己的为准。例：#1 明说 `[10-01, 11-20)`，#2 明说从 11-20 起，#2 被删。11-20 是 #1 自己说的，不因为 #2 也在这一点上就不给。

给出者定了，再分两种：

- **明说的一端**（写入时给了这个日期，或明说了「一直到以后」）：它是这一项贡献的内容。这一项贡献被一次删除拿走了，这一端就不给。
- **解析出来的一端**：其余的端点都是解析出来的——默认终点停在下一个变化点上，纠错的默认区间，只给了起点的撤销的终点，回退或回到合并基时写回的项的区间，按常量补值的那一段的两端。记这个区间的块被一次删除列入了，这一端就不给。

**按端分，不按块分。** 一端是明说的还是解析出来的，看写入头事件里这一项的区间参数（`ops/<i>/valid`）对这一端怎么写：起点是 `given` 或 `now`、终点是 `given` 或 `open` 的，是明说的；`next_change`、`corrected_span`，以及没有区间参数的项（回退与回到合并基写回的项、补值）的两端，是解析出来的。一个区间块可以一端明说、一端解析（例：起点明说、终点是默认终点，块里带着给出挡点的项）；块因那个依赖被列入时，只有解析出来的那一端不给，明说的那一端照「这一项贡献在不在」判。

**开口也是一端。** 「一直到以后」与一个日期一样，由给出者决定给不给：被删的写入明说了没有终点，这句话同样是它的内容。不给时照第 2 节缺着；`valid_to_inclusive` 随 `valid_to` 一起给、一起缺。

「被一次删除拿走 / 列入」与值的判据是同一条：那次删除是在这条记录记下之后确认的、仍待执行的，撤回的不算。删除执行之后怎么认，与值一样留给落账执行的那一步（08-open-questions 第⑤条）。

**行的一端。** 一行的一段由所选各字段的格子合成（见第 2 节「在读的五步里的位置」），行的端点 P 可能同时是几个字段的端点。落在 P 上的每个所选字段的端点（以及存在与否的端点）都不给，行的这一端才不给；只要有一个出自没被删的内容，P 照给。

**会多藏的三种。** 都偏向少给，不会多给，一并留待以后收窄：

- 一个区间所依赖的项只是被一次删除重述了（它说的日期本身并非出自被删的内容），这个区间的块也会被那次删除列入（09-event-format §3.5 规则 1），解析出来的那一端跟着不给。
- 明说的一端按「这一项贡献在不在」判，不按「说这个日期的那句话在不在」判：只删了值的证据、说明日期的那句话还留着（`sources` 里还读得到它）时，这一项贡献没有了，日期也跟着不给。所以不能把规则读成「只有说它的那句话被删了，日期才不给」。
- 另有佐证的值在历史上被多藏（值那一侧已有的情形）。

「版本表：区间保留」那句写准：保留的是这条记录**在记录时间上**的起止（它从哪次操作起有效、到哪次操作为止），那是操作号，不是用户说的话。

### 2. 不给的端点怎么表示

- **缺着，不换成别的值。** `valid_from` 或 `valid_to` 这个键不出现，这一段带 `partially_deleted`。不写成 `null`：`valid_to: null` 的意思是「一直到以后」，那是一个值。也不按删除之后的状态重算一个终点：按记录时刻读到的是当时的状态去掉被删的内容，不按定义重算（03-deletion 原有的规定）。
- **什么都不剩的段不列。** 一段的每个值都不给、并且它的起点也不给，这一段不出现在结果里：它只剩一个终点，列出来等于把被删写入的范围又画了一遍。值都不给而起点还在的段照常列（例：#1 写 5000，`[10-01, ∞)`；#2 写 4000，`[11-01, ∞)`，之后被删；#3 写 3000，明说 `[10-15, 11-10)`。按 #3 那一刻读，最后一段的值出自 #2、不给；它的起点 11-10 是 #3 明说的终点、照给；它的终点是 #2 明说的「一直到以后」，#2 被拿走了，所以也不给：`[11-10, —)`）。
- **在读的五步里的位置。** 按区间读的次序是定好的（04-contract）：字段条件、合并相接且所选字段取值相同的段、与请求的区间求交、`valid_from` / `valid_to` 的条件、截断。不给的东西这样放进去：
  - 合并照旧先做，做在真实的段上；一个不给的值不与任何给出的值相等，只与另一个不给的值相等。所以带着它的段不与给出值的邻段合并（哪怕两边的值其实相同：并了就等于说出了它），而相邻的、值都不给的段并成一段，被删写入内部的切点不留下来。
  - 端点在合并**之后**判，判的是合并出来的那一段：只因没选的字段、或只因被合掉的切点而存在的边界，随合并消失，与今天一样。
  - 一段的终点不给，不因此与后一段并成一段：并了就得给整段一个值，而哪一部分是哪个值正是不能说的。
  - 求交与条件只凭给出的端点（第 4 节）。
  - 截断之后照样不给：终点不给的段这一端仍然缺着，不截成请求的终点，那等于替被删的内容说「这一段一直延续到那里」。
- 上面第 2 种来路的结果是：`[10-01, 11-10) 5000`；`[11-10, —) 3000`，带 `partially_deleted`。没有第三段。
- 事件类表没有区间，不涉及；它的时间字段是值，已按值处理。

### 3. `changes`

- 条目的区间两端各自照第 1 节判，不给的那一端缺着，条目带 `partially_deleted`。
- 只因被删写入内部的切点而分开、去掉那个切点之后相邻、两侧又都是不给的值的小段，并成一条。`as_of` 与 `changes` 对同一段历史给出的日期因此一致：`as_of` 里看不到的日期，`changes` 里也看不到。判断「这里有没有变化」时两个不给的值仍然算不同：从一个被删的值改成另一个被删的值，是一次变化。这与第 2 节「不给的值只与另一个不给的值相等」不相抵：那一条比的是同一个状态里沿业务时间相邻的两段，这一条比的是同一个时刻上一次操作的前与后。
- 条目的区间用一个两端可缺的类型。契约里通用的区间类型（两端必有，`null` 表示开口；事项的区间、回执都在用）不动。

### 4. 筛选、排序与翻页

- **筛选**（`valid_at`、`valid_during`、对 `valid_from` / `valid_to` 的条件）：凭给出的端点就能确定的才算命中；要凭不给的那一端才定得了的，不命中。否则换着日期问几次，就能把不给的那个日期夹出来。代价要说明白：`as_of` 带着落在 `[11-10, —)` 里的 `valid_at` 读，读不到 3000，而 3000 没有被删、不带 `valid_at` 的同一次读会列出它。有段因此被留在结果之外时，这次读的结果带 `partially_deleted`（`as_of` 结果上的可选字段，与行上的同名；结果是空的也带）：「那时没有值」与「说不了」不能看起来一样。契约里的标记汇总 `marks_summary` 只在 `sql` 的结果上，不扩到这里。
- **翻页位置在删除之后过期。** 一个翻页位置发出之后，这个租户里有删除被确认或被撤回，凭这个位置读下一页回 `handle_expired`，与恢复之后、派生表重算之后的做法相同；调用方从第一页重读。理由：不给的内容的范围在两页之间变了——多了一次删除，少了一次（撤回），一段从有起点变成没有、或从列出变成不列——同一轮翻页就可能把一段给两次，也可能**漏掉**一段，而漏是没法从结果里看出来的。删除很少发生，位置本来一小时过期，代价是偶尔重读一次。
  - 所以 `query` 的后续页上没有不给的端点要处理：后续页按第一页那一刻读，那之后没有删除，就没有什么要不给的。
  - `history` 的 `as_of` 翻页时，不给的范围在一轮翻页里是固定的。
- **排序**：状态类表按实体、再按起点排。起点不给的段排在同一实体的各段之后，不凭它的起点定位置。同一实体有几段起点不给时，它们之间照真实起点的先后排：这只透露它们的相对次序，可以接受。
- **翻页位置里的键**：位置只签名、不加密，拿到它的人能读出里面的键，所以**真实的日期不能为了排序而写进位置**。起点不给的段，位置里起点那个键是 `null`；同一实体可能有不止一段这样的段，它们的键相同，所以键末尾多一个序号：起点不给的段取它在本实体这类段里的先后序号，其余段取 `null`。上一条保证了一轮翻页里这个序号不变。**只加在 `history` 的 `as_of` 上**：位置在删除之后过期（上面一条），`query` 的后续页读不到要不给的端点，它的状态类表位置不动，免得让所有状态类表的翻页位置白白过期一次。
- `as_of` 在状态类表上的位置，格式版本因此加一。升级之前发出的位置回 `handle_expired`（原因 `format_changed`，重读即可），不回「参数不对」：调用方没有做错什么。

### 5. 展示

MCP 的文字与命令行里，缺着的一端写成「（已删除）」。现在缺着的一端会被当成开口（起点缺成了「直到某日」，终点缺成了「某日起」），起点缺着时区间这一列还会整个消失：这两处一并改。

## 没选的做法

- **照旧给出日期。** 日期是用户说的话；规格自己的例子已经写了不显示。
- **把端点换成删除之后的状态里的那个值**（第 2 种来路里把 3000 那段的终点写成「一直到以后」）。那是按定义重算，读到的不再是那一刻的状态，而且与删除那一刻起的读分不出。`timeline` 给的是「最近一次给出的区间」，它本来就是这个含义，所以它可以；`as_of` 不是。
- **把两段并成一段、值都不给。** 藏住了日期，但把 3000 这个没被删的值也丢了。
- **另加一个键说明哪一端不给。** 键缺着加上 `partially_deleted` 已经说清楚了；多一个键是多一处要每个读者都处理的东西。
- **在翻页位置里放真实的日期、只是不在结果里给。** 位置能被读出来。
- **删除夹在两页之间时接着翻，接受同一段出现两次。** 同样的机制也会漏掉一段（一段在两页之间变得什么都不剩、或拿回了起点，后面各段的序号跟着变），漏比重复更糟，而且看不出来。让位置过期一并解决了重复、漏、以及一轮翻页跨着两种不给的范围这三件事。
- **为了找到端点的出处而改存储。** 不需要：格子指向的那一项的区间（或最近一条重述）、写入时原样记下的区间参数，读的时候都在，足以分出一端是明说的还是解析出来的、出自谁。

## 怎么验

- 三种来路各一条固定用例，删除走真实的操作：被删的话自己说的日期；别的写入的默认终点；`changes` 的内部切点。每条在全部输出（含 MCP 与命令行的文字）里搜不到那个日期。
- 第 2 种来路：两段，第二段终点缺着、带标记，没有第三段；撤回删除之后三段原样回来。
- 被删的写入明说「一直到以后」：它那一段的终点缺着，不是 `null`；`valid_to_inclusive` 一起缺。
- 解析出来的一端的各种来路各一条：默认终点、纠错的默认区间、只给起点的撤销、回退写回的项、按常量补值的那一段（它的终点出自一次被删的写入）。
- 两边都有端点落在同一点上、其中一项被删：那一点照给。
- 值都不给而起点还在的那一段：照常列出，起点照给。
- 一行由两个所选字段合成、同一点上一个字段的端点出自被删的内容、另一个不是：行的这一端照给；只选前一个字段时不给。
- 两次删除（第一次重述出的端点，被第二次删掉它的给出者）：第一次之后给，第二次之后不给。
- 只删值的证据、留着说明日期的那句话：日期不给（多藏的第二种，照实）。
- `as_of` 与 `changes` 对同一段历史给出的日期集合相同。
- 五步的次序：不给的值不与等值的邻段合并；合并之后才判端点；截断之后终点仍缺。
- 筛选：`valid_at` 落在终点不给的段里，不命中，结果带 `partially_deleted`，结果为空时也带；换着日期问，问不出那个日期在哪。
- 翻页：发出位置之后确认一次删除、撤回一次删除，各自凭旧位置读下一页回 `handle_expired`；没有删除时照常。`history` 的 `as_of` 上同一实体三段起点都不给，逐页读不漏、不重；翻页位置里搜不到任何不给的日期。
- 升级之前格式的位置回 `handle_expired`。
- 没有任何删除时，全部读法的输出与改动之前逐字节相同。

## 分步交付

1. 这份决定记录。
2. 翻页位置在删除确认或撤回之后过期（一份改动，先做：它独立成立，并且让后续页不必再处理不给的内容）。
3. 规格与实现，拆成两份，各自独立审查：
   - **3a**：`history` 的 `as_of`。端点的给出者与判据（`changes` 也用这一块）、结果里的缺与标记、什么都不剩的段不列、`valid_at` 与沿用的业务时间条件、排序与序号键、位置的格式版本、两处渲染，连同上面与 `as_of` 有关的测试；并按开工前的核对修订本文（下面的「修订」）。
   - **3b**：`changes`。条目区间两端的判据、内部切点的并段、两端可缺的区间类型，以及「`as_of` 与 `changes` 给出的日期集合相同」那条测试。
4. 三种多藏的收窄，另行决定。

## 修订

开工前对着实现时的 main 核对之后改的四处（3a 里一并改）：

1. **判据只算仍待执行的删除。** 原文写「待执行或已执行都算」，那是在值的判据收窄之前写的；值的判据已收窄到仍待执行，执行之后归 08-open-questions 第⑤条，端点跟着同一条。
2. **明说与解析出来的一端按端分。** 原文写「凡是记在自己的一个块里、带着它所依赖的项的区间，它的端点都是解析出来的」，照字面，上面第 2 种来路里 #3 的区间块（起点明说、终点停在 #2 的变化点、带着 #2）两端都算解析出来的，块被列入时 11-10 也不给，结果与本文自己写的 `[11-10, —) 3000` 相抵。改成看头事件对每一端的写法。
3. **结果级的标记挂在 `as_of` 的结果上**，叫 `partially_deleted`，与行上的同名；原文说的「标记汇总」只在 `sql` 的结果上有。
4. **序号键与位置格式只加在 `history` 的 `as_of` 上。** 位置在删除之后过期（第 2 步）之后，`query` 的后续页读不到要不给的端点；原文写「状态类表的键」，会让所有状态类表的翻页位置白白过期一次。
