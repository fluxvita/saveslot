# 决定：冲突判据的对称只在写明的范围内承诺，规则不动

> 2026-11-24 决定。改的是规格的说法（K8 与 data-model「冲突判据」的对称一条），不改任何判定规则，不改事件格式。

## 1. 改了什么

1. **对称一条**（[`../../spec/03-data-model/09-references-conflict-sync.md`](../../spec/03-data-model/09-references-conflict-sync.md)「冲突判据」）原来写成对任何两次带同一个 `ver` 的写入都成立。现在写明范围：状态类表上，两次都不传终点、都没有显式指向证据、都没有让所见版本里的变化点消失。范围之外不作承诺，并列出已知的三处 (a)(b)(c)。
2. **K8**（[`../../spec/02-architecture.md`](../../spec/02-architecture.md) §3）里重复的那句同样加上范围，指向对称一条。
3. **测试矩阵**里「冲突判定对称」「不冲突的并发写入可交换」「不相交的写入可交换」三条性质加上同一个范围。
4. **组值的例子**："W 与 L 都只把 a 写成同一个值，两种顺序都不冲突"只在状态类表上成立；事件类表、无时间表上判据不比值，改成分两种表写。
5. 讲解里重复这些说法的几处（第 4、7、10、12 章）与根目录的中文 README 一并改。
6. 新增断言索引 [`../../spec/11-claims.md`](../../spec/11-claims.md)：这一条和它的三处例外各占一行，各有测试。

## 2. 为什么

- **原来的说法不成立，而且有记录。** 三处反例早已写在待定清单里，也各有一条固定用例照现行规则的结果断言。规格正文却仍把对称写成全称断言：读规格的人会相信一条不成立的话，这比不写更糟。
- **范围取性质测试实际守着的那一块。** 现有的性质测试生成的就是"同一版本、都不传终点、不指证据、不抹所见变化点"的两次写入，两种顺序比是否冲突与合并后的值。规格承诺的范围与测试覆盖的范围一致，不多写一句没有证据的话。
- **三处例外都不丢写入，也不让候选悄悄生效。** (a)(c) 是终态不同，(b) 是事项的种类不同；"版本对不上不覆盖"这半句 K8 不受影响。

## 3. 为什么不改规则

让 (a)(c) 也对称需要改默认终点在合并时的解析，或把同值的显式 × 默认也按相交处理；让 (b) 对称需要让待确认的写入也算 L。每一种都会改变已经写下的日志在重放时的判定，属于规则版本的变化，要单独评估。这件事留在 [`../../spec/08-open-questions.md`](../../spec/08-open-questions.md)，定了之后索引里对应的行随之翻转。

## 4. 重启条件

- 评测或真实使用里出现因 (a)(b)(c) 造成的错误结果；
- 或者要把对称的范围扩大到显式区间的写入：先有覆盖那个范围的性质测试，再改规格的说法。
