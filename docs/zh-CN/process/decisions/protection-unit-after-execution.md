## 1. 问题

状态类表上，一次写入在一个目标（一个字段，或"存在"）上可以有几项，每一项的区间记在 `span/<目标>/<k>`。这一块是由别的贡献求得的内容，带 `deps`：`deps` 里任何一项被删除或被重述，它就列入那次删除的位置列表，删除到期执行时清掉（事件格式 §3.5）。

规格有四处要读"当时的区间块"：

1. 偏离二：一项写入时生效的部分与因删除才生效的部分并在同一个下标下时，受不受保护按写入时的区间分。
2. 原有项的下标留在重放里的哪一段。
3. 新编出的下标从哪一项分出（编号，与前提声明按项覆盖的那一部分）。
4. 采纳候选时填上的撤销当时的区间：重放用它分"当时填上的部分不盖住采纳项、之后多出来的部分盖住"。

一次删除到期执行之后再来一次删除，前三处没有可读的东西。第四处由删除事件重新给出、以最近一次为准，但这样有两个毛病：

- **与先后有关。** 例（状态类表，`f2` 必填，`f3` 可选）：#13 `f3 = x`，`[11-10, ∞)`，证据 SX；#15 `f3 = y`，`[11-05, 11-15)`，证据 SY；#21 撤销，起点 11-06、默认终点，解析为 `[11-06, 11-15)`；之后采纳一个 `f2 = 6`、`[10-01, ∞)` 的候选，填上了 #21 的空洞。一次删 {SX, SY}：#21 重新解析为 `[11-06, ∞)`，比当时多出 `[11-15, ∞)`，`f2 = 6` 到 11-15。先删 SY：#21 成为 `[11-06, 11-10)`，重新给出的"当时的区间"也成了它；再删 SX：多出来的是 `[11-10, ∞)`，`f2 = 6` 只到 11-10。
- **留下被删内容给出的端点。** 上例一次删两句的结果里，11-15 这个日期只出自被删的 SY，却作为段的端点留在删除结果里。

## 2. 约束

- 不漏删：不能另存一份不随删除清除的区间或分界点。
- 删除不增加未决事项；写入时全部生效的写入不因一次不相干的删除退回候选。
- 值与生效状态只取决于日志与被删集合，与删除的先后、是否已到期执行无关。下标只是寻址，不在这条里。

## 3. 可选做法

- **另存写入时的分界点，不随删除清除。** 分界点是别的贡献给出的，可以正是被删的内容。违反不漏删。
- **按分界点的给出者把相邻的项并成区域，按区域判保护。** 给出者的名单记在 `span` 的 `deps` 里，随块一起被清，要另存一份不随删除清除的名单；没有区间时，重放出的段与写入时的区域对不上（段数相同也可能是一条分界消失、另一条出现）；用前一次删除重新给出的块作基线，与从原始块算并不相等，上面第四处就是例子。
- **保护的单位取一次写入在一个目标上的全部项，不取区间。**（采用）

## 4. 决定

1. **偏离二的单位是（事件, 目标）。** 普通写入或撤销在一个目标上写入时各项全部生效（生效或佐证）的，任何重放里它在重放解析出的整个区间上保持生效，延伸出写入时区间的部分也在内。写入时有一项没生效的，各项都按重放判。判据只读写入事件给出的各项状态；状态只随这项贡献自己的来源清除，所以与删除的先后、是否已到期执行无关。字段组里仍逐字段看。
2. **不经这条判据的事件**：带回退记录或采纳记录的基础写入、确认触发的基础写入。它们生效与否照所属的操作。一次回掉写入时是待确认还是已生效，看同一操作里有没有指向它的待确认事项（之后的删除新开的待确认事项也指向它，不算），不读写回项的状态。
3. **写入时一部分生效、一部分没生效的写入不受保护。** 状态类表上它只有一种：带过期 `ver`、显式指了证据的同值写入，仍同值的部分成了佐证、已被改掉的部分成了候选。之后的删除（或撤回）让它不再同值时整段重判；重放里没生效的部分归这次写入原来的事项——未决的并入，已由人解决的被那次决定关闭，已因别的原因被取代的随它关闭——都不新开事项，后两种在预览与回执里单列。
4. **撤回时的保持生效同一个单位。** 只在撤回前这个（事件, 目标）的各项全部生效时才记；以它为基线的写入，所见版本须不早于它各项全部生效起的那次操作。两项删除的宽限期重叠时，写在后一项删除之前的写入没见过后一项才推生效的部分，不能把它也保住。
5. **采纳填上的撤销按整条判。** 记录里列为填上的撤销整条不盖住采纳项；没列到的整段盖住。不再记、也不再读填上的撤销当时的区间，事件格式里去掉 `take_filled`。
6. **下标。** 原有项的写入时区间块已被到期执行的删除清掉时，按"由删除编出的下标"同样处理：留在与它最近一次给出的区间相交的第一段上，"从哪一项分出"也用这个区间。清掉那一块的删除必定重述过它，所以总读得到。曾重述为 `dropped`、之后又成为贡献的下标按起点顺序用回。判一个块的 `deps` 有没有被删，按（事件, 目标）认，不按下标。
7. **删除或撤回作为冲突判据里的 L**：它记下"实际改了值的区间"的块，有任何一块列在当前被删集合里任一项删除的位置列表里（事件格式 §3.5 规则 1：`deps` 里有一项被删除，或被那次删除重述；与那次删除是否已到期执行无关）时，当作在整个冲突单元上改过值。

## 5. 理由与代价

单位取整个目标，是因为能安全留下的只有"这次写入当时各项是什么状态"，留不下"哪一段是什么状态"：段的边界出自别的内容。同一个理由用在采纳填上的撤销上。

L 的区间按被删集合判、不按是否已到期执行判：一个块的 `deps` 里有被删的贡献，它记下的区间就已经不可信，到期执行只是把这件事落到存储上。按是否已执行分叉，会让被重判的旧写入随执行与否得出不同结果，与第 2 节的约束相抵。所以待执行期间与执行之后判出的结果相同。

代价有三处，都是少保护或多留一道确认，不是值算错：

- 带过期 `ver` 的佐证被切成佐证与候选两部分的写入，删掉基础来源后佐证过的那一段不再保住值。后续可以细化：这种写入在重放里不再同值时仍按佐证的拆法逐段判（所见版本之后没被改过的部分生效）；它与高影响判定、事项归属的关系还没有定。
- 因删除只部分生效、宽限期内又被别的写入当作基线的写入，撤回时那部分照样退回。
- 已填上的撤销之后因删除延伸出的部分不再盖住采纳项。
