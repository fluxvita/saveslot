## 1. 开发前必须定的

### 决定 1 单位词表

- **问题**：`quantity` 字段的单位代码、量纲、换算系数进编译后的定义（事件格式 §7），是事件内容；规格只写了"倾向 UCUM 子集 + ISO 4217"。
- **做法**：甲——直接用 UCUM 的写法（英里是 `[mi_i]`、磅是 `[lb_av]`）；乙——自己的一张固定词表，代码取常见写法，另列 UCUM 对应；丙——开放任意单位字符串、不换算。
- **决定：乙。**
  1. **词表是固定清单**（`units@1`），不做单位表达式的代数运算。清单见 `03-data-model/10-types-and-units.md`「单位词表」：长度、质量、时长、体积、能量、频率、速度、无量纲、温度、货币。
  2. **代码**：ASCII、区分大小写。公制单位与 UCUM 写法相同（`km`、`kg`、`min`、`kJ`、`mL`、`/min`、`km/h`）；英制用常见缩写（`mi`、`ft`、`in`、`yd`、`lb`、`oz`、`mi/h`），词表里另列 UCUM 代码，供将来对外互操作。
  3. **量纲标识**：小写英文词（`length`、`mass`、`duration`…）；货币是 `currency:<代码>`，每种货币自成量纲；温度是 `temperature:<代码>`。
  4. **换算系数** `to_base`：换算到该量纲基准单位的精确十进制字符串（`mi` → `"1609.344"`）。同量纲 = 量纲标识相同。换算 = 乘以源单位的系数、除以目标单位的系数，按字段精度舍入（决定 2）。
  5. **货币**：代码是 ISO 4217 的三字母代码，现行有效的都接受；不换算。
  6. **温度第一版不互相换算**：`Cel`、`degF`、`K` 各自成量纲（换算带偏移，一个系数表达不了）。将来给 `unit` 加可选键 `offset` 即可，不改已有定义。
  7. **词表外的单位**：编译草稿时报 `validation_failed`（`unknown_unit`），列出同类候选；写入时单位不在词表或量纲不同报 `validation_failed`（`unit_mismatch`）。确实没有合适单位的量，用 `decimal` / `integer` 字段并在说明里写清单位。
- **理由**：甲对模型和人都不友好（方括号写法几乎没人这样说），而且现有例子、读结果里已经在用 `mi`、`km`。丙放弃了"同量纲自动换算"与"单位写错能被挡住"。固定清单没有歧义，重放不依赖任何解析器。
- **事件格式**：`compiled` 里 `unit` = `{code, dimension, to_base?}`，与现有结构一致；货币、温度没有 `to_base`。`ctx.literal_checker` 的 `literal@1` 包含 `units@1`。
- **契约**：新的 `details[].code`：`unknown_unit`、`unit_mismatch`（若已有同义的码，以契约为准并回改数据模型）。
- **第一版**：做。

### 决定 2 默认精度与舍入

- **问题**：同值判定"按字段声明的单位与精度"，但 schema 文档里没有精度的键，默认值没定（审查 P1-7、事件格式待定项 2）。
- **决定**：
  1. `quantity`、`decimal` 字段可声明 `scale`（小数位数，0–12）与 `rounding`（`half_up` / `half_even`）。
  2. **默认 `scale`**：货币取 ISO 4217 的最小单位位数（CNY 2、JPY 0、KWD 3）；其余 `quantity` 与 `decimal` 取 6。
  3. **默认 `rounding`：`half_up`**（四舍五入，恰在一半时远离零）。`half_even` 可选。
  4. 写入的值（换算后）小数位数超过 `scale`：按 `rounding` 舍入后落账，回执 `warnings` 给 `rounded`；原始值留在写入头的原始传参里。
  5. 同值判定、`min` / `max` 校验、疑似重复都在舍入后的值上做；字面命中比原始值。
  6. 派生字段的精度由编译器推断：`sum` / `min` / `max` 沿用输入字段的；`avg`、除法取输入的 `scale` 与 6 的较大者；`count` 是整数。
- **理由**：`half_up` 与 PostgreSQL `round(numeric, n)` 的行为一致，派生规则里写 `round()` 与内核的舍入因此是同一种，两个后端不需要另写实现；也是多数人对金额的预期。6 位足够容纳常见换算（5 km = 3.106856 mi）。
- **事件格式**：`compiled` 的 `precision` = `{scale, rounding}`，结构不变；**§7 例子里的 `half_even` 改成 `half_up`**。
- **契约**：schema 文档的字段加 `scale`、`rounding`；`warnings` 加 `rounded`。
- **第一版**：做。

### 决定 3 建 slot 时的默认策略

- **问题**："兼容的小改动按策略自动生效"，策略内容没定（已知 B10、事件格式待定项 3）。
- **决定**：
  1. **`auto_apply` 的取值**（每个值对应决定 15 表里的一类改动）：

     | 值 | 改动 |
     |---|---|
     | `add_table` | 新增基础表 |
     | `add_derived_table` | 新增派生表 |
     | `add_optional_field` | 新增可选字段 |
     | `description` | 只改表或字段的说明 |
     | `rename_unused` | 改名，且最近 30 天没有**提交者以外**的连接实例按旧名读写过它 |
     | `loosen_constraint` | 放宽约束：必填改可选、放宽 `min` / `max`、枚举加值、加大 `scale` |
     | `duplicate_keys` | 改疑似重复的判据 |
  2. **默认策略**：七个值全开；`effective_value_rule: "keep_current"`；`rank` 按事件格式的初值；`high_impact`、`user_session_only` 为空数组。
  3. **一份草稿自动生效，当且仅当它的每一项改动都落在 `auto_apply` 里**；否则整份草稿进待确认。新建 slot 总是直接生效。
  4. `user_session_only: [{item_kind, decision}]` 是为"某类处理只接受用户会话确认"留的位，第一版恒为空、内核不读它。
- **理由**：这七类都不改动已有的值、不让旧写入失败、不让现有读取读到不同的东西。其余改动（删、改类型、改单位、收紧、改规则、改时区）要么丢数据，要么改变读到的值。
- **事件格式**：`slot.policy_set` 的 `auto_apply` 取值集合如上；例子里的 `["add_optional_field","rename_unused"]` 换成默认的七个。
- **契约**：`SlotPolicy.auto_apply` 的取值集合如上（契约暂用的三个值是它的子集）。
- **第一版**：做（只有默认策略；修改策略后续）。

### 决定 4 读取记录里查询条件的结构指纹

- **问题**：read_log 要按完整形状记，查询条件"记不含用户值的结构指纹"，算法没定。
- **决定**：指纹是一段**规范化后的文本**，直接存文本，不存哈希。
  - `query`：一个 JSON 对象按 RFC 8785 编码——表 ID、所选字段 ID（排序后）、条件树（运算符 + 字段 ID，**每个字面量换成 `"?"`**，`in` 的列表整体换成一个 `"?"`）、排序（字段 ID + 方向）、是否带了 `limit` / `cursor`（只记有无）、业务时间参数的种类（`valid_at` / `valid_during` / 无）。
  - `sql`：把语法树里的表名、字段名换成 ID，每个常量换成 `$n`，`IN` 列表折成一个占位符，**去掉列别名、表别名与注释**（别名是调用方起的文字，可能含用户内容，换成位置序号），再反解析成文本。
  - `history`、`sources`、`catalog`、`pending`：只记操作、模式与目标的不透明 ID；`sources` 的搜索词不记。
  - 业务时间条件照旧另记（影响查询要用），它是 read_log 里唯一来自调用方的值。
- **理由**：存文本比存哈希好排查，而它本来就不含值；规范化到 ID 之后改名不影响匹配。
- **事件格式**：无（read_log 是本地运行状态）。**契约**：`reads.list` 给用户会话的"查询条件"就是这段文本。
- **第一版**：做。

### 决定 5 `visibility` 的最小类型

- **决定**：

  ```ts
  type Visibility =
    | { kind: "all" }
    | { kind: "scoped";
        slots: Array<{ slot: SlotId;
                        tables?: Array<{ table: TableId; fields?: FieldId[] }> }> };
  ```

  - 没列出的 slot 不可见；slot 下不给 `tables` = 该 slot 全部可见；表下不给 `fields` = 该表全部字段可见。
  - 不可见的表在目录里不出现；查询、受限 SQL、写入引用到它，与引用不存在的表一样报 `not_found`（不泄露"有这张表"）。事项、源数据按所属 slot 过滤。
  - **派生表可见，当且仅当它依赖的全部（表，字段）都可见。**
  - 第一版服务层恒传 `{kind: "all"}`；内核把 `scoped` 实现到 slot 与表两级（测试用），带 `fields` 时报内部错误"第一版不支持"。行级限制将来以新的可选键加入。
- **理由**：白名单比黑名单安全（新表默认不可见）；三级嵌套与"用户 → slot → 表 → 字段"的资源层级一致，将来加数据权限不改 `ops` 的签名。
- **第一版**：做（类型与两级实现）。

### 决定 6 标识的写法

- **决定**：一张表，落在 `01-objects.md`「标识的写法」。要点：
  - 全局唯一的（租户 `tn_`、用户主体 `u_`、连接实例 `ci_`、节点 `n_`）：128 位随机数，Crockford Base32，26 个字符。
  - 租户内唯一的（slot `sl_`、源数据 `s_`、事项 `pi_`、草稿 `d_`、迁移 `m_`、派生分区 `p_`、恢复 `rs_`、读取 `rd_`）：80 位随机数，16 个字符。
  - 行 `r_`、实体 `e_`：UUIDv7 的 128 位写成 26 个字符（按时间有序，索引局部性好；它带创建时间，已在"删除后保留的元数据"里写明）。
  - 表、字段、规则：短 ID `t<n>`、`f<n>`、`r<n>`，表与规则在租户内递增，字段在表内递增，删掉的不复用。
  - 不是标识的：`ver`（`v<操作号>.<恢复次数>`）、事项版本 `iv_…`、删除确认句柄 `dc_…`、翻页游标、令牌 `slt_…`（密钥，只在控制面存哈希）。
- **事件格式**：例子里的 `c_7Hq2` 改成 `ci_…`；§1.4 的表按此补全（待定项 4 关闭）。
- **第一版**：做。

### 决定 7 派生规则的读集

- **决定**：第一版每次派生刷新的读集只记（规则版本，基础表 ID，派生行的 `partition_id`，读到的日志位置）。带 `WHERE` 的规则不另记谓词形状；重算范围分析不出的规则按整个租户一个分区记。将来要记谓词形状时，以 `write.derived` 的 `target.reads[]` 里新增可选键加入。
- **理由**：第一版的重算范围分析只识别分组聚合与按业务时间分桶；记到分区已够删除级联与影响查询（宁可多报）。
- **第一版**：做。

## 2. 审查里没覆盖的

### 决定 8 同值判据

| 字段类型 | 同值当且仅当 |
|---|---|
| `quantity` | 换算到字段声明的单位、按 `scale` 舍入后，数值相等（`"1.0"` 与 `"1.00"` 相同） |
| `decimal` | 按 `scale` 舍入后数值相等 |
| `integer` | 数值相等 |
| `text` | 做 Unicode NFC 规范化之后逐码点相同。不去首尾空白，不折叠大小写 |
| `enum` | 取值相同（区分大小写） |
| `boolean` | 相同 |
| `date` | 同一天 |
| `zoned_datetime` | 同一瞬间**且**时区相同（时区不同，"哪一天"可能不同） |
| `ref` | 指向同一行或同一实体（临时名先解析成 ID 再比） |
| 空 | 空与空相同；空与任何值不同 |

- `text` 落账前做 NFC 规范化（原始写法留在写入头里）。状态类表上"同值"仍要求在解析出的整个区间上都相同。
- **第一版**：做。

### 决定 9 清空字段

- **做法**：甲——不提供清空；乙——`null` 是一次贡献；丙——`null` 不是贡献。丙的后果：清空在删除重放里等于没发生，更早的值会回来。
- **决定：乙。**
  1. `set: {"note": null}` 清空一个可选字段。它是一次贡献：值为空，值来源照常是这次写入的证据。
  2. 必填字段不能清空：报 `validation_failed`（`required_missing`）。不想要这一行，用撤销。
  3. 删除重放时空值贡献与其他贡献一样参与"最后一个仍在的贡献"。它的来源被删，更早的值回来。
  4. 行的存在：必填字段不可能有空值贡献，所以"每个必填字段至少一个仍在的贡献"不受影响；"至少有一个字段有仍在的、不是常量补值的贡献"里的贡献指**非空**贡献。
  5. 状态类表上，可选字段在一段区间上为空是"值为空"，不是无值区间（无值区间说的是必填字段没有值、实体在这段不存在）。可选字段的 值 ↔ 空 是取值变化，算挡点。
  6. 新增时没带的可选字段没有贡献；新增时显式写 `null` 与"原来没有值"同值，按同值规则是无操作或佐证。
  7. 字面命中：`na`。
- **事件格式**：`fields/<字段ID>` 的 `value` 可以是 `null`（§1.3 已有）。**契约**：`set` 的值允许 `null`。
- **第一版**：做。

### 决定 10 `ref` 的目标被撤销或被删除之后

- **决定：引用不级联。**
  1. **写入时**（依赖当前状态的校验，判定顺序第 5 步）：`ref` 的目标必须存在、在声明的那张表里、未撤销、不在某次已确认的删除里。否则 `validation_failed`（`ref_not_found` / `ref_wrong_table`）。指向状态类实体时，实体须至少在某段业务时间上有值。
  2. **目标被撤销**（高影响 ② 确认之后）：引用方不动，`ref` 字段保留原 ID。读取时该值带 `ref_state: "revoked"`。撤销被 `undo` 之后标注自然消失。
  3. **目标被隐私删除整行删掉**：不被引用挡住。引用方不动，读取时带 `ref_state: "deleted"`；行 ID 是不透明标识，不是被删内容。删除预览单列"仍引用被删行的行"。
  4. **高影响 ② 怎么数"仍被引用"**：当前版本里未撤销的行，其 `ref` 字段的**生效值**指向目标（状态类表：任何一段指向它都算）。候选、待确认里的引用不算。
  5. **状态类表**：只有撤销整个实体（不带区间）才判 ②；带区间的撤销之后实体仍在，不判。
  6. 引用方对一个已撤销 / 已删除的目标原样带回同一个 ID：同值，无操作或佐证，不重新校验。
- **理由**：级联删除会让一次撤销或删除波及用户没点名的行；置空又等于替用户改了值。保留 ID 加读时标注，信息不丢，决定留给人。
- **事件格式**：无（`ref_state` 读时现算）。**契约**：读结果里 `ref` 值的 `ref_state`；`deletion_preview` 加"仍引用被删行的行"一项。
- **第一版**：做（随 `ref` 字段类型）。`08-open-questions.md`"`ref` 的删除行为"关闭。

### 决定 11 疑似重复

- **决定**：
  1. `duplicate_keys` 只能声明在事件类表与无时间表上；状态类表有 `entity_key`，声明了报编译错误。
  2. **只在新增（`insert`）且已生效时判**。变更、纠错把一行改成与别的行相同时不判。
  3. **和谁比**：同一张表当前版本里未撤销、不在已确认删除里的行的生效值，含本请求前面的 op 刚新增的行。候选、待确认里的值不比。
  4. **怎么算命中**：某一组键的每个字段都按同值判据（决定 8）相同；任何一方在键字段上为空就不命中。多组键任一组命中即命中。
  5. **事项**：每个新增的行一个 `flagged` 事项，列出命中的行（最多 10 个，按最近写入排）与命中的是哪一组键。写入照常生效，回执 `saved`。
  6. **之后**：被标记的行被撤销、被隐私删除，或它与列出的行都不再命中（任一方被改、被撤销、被删除）时，事项标"已被取代"（`overwritten` / `deleted`）。这是机械判定，**不要求写入方读过事项**（「不过期」里"没读过只刷新"的规则保护的是未生效的候选与提议，`flagged` 没有这样的东西）。列出的行只是部分不再命中时，刷新条目。
  7. 判定结果记进基础写入事件，重放不重判；删除重放按原则 ② 重算。
- **事件格式**：`write.base` 的 `duplicate` 块已有，形状补"命中的键组"。**契约**：`flagged` 事项详情列出命中的行与键组。
- **第一版**：做。

### 决定 12 键字段写错了怎么改正

- **做法**：甲——允许用 `correct` 改键（作用于整个实体，撞键时拒绝）；乙——键不可改，撤销重写。
- **决定：乙（第一版）。**
  1. 键字段不可改：`set` 里出现键字段且值与实体的键不同，报 `invalid_argument`（`key_field_changed`），不分意图。
  2. 写错键建出了一个新实体时：**撤销那个实体（不带区间），再按对的键写入**。写错的实体与它的键留在历史里，可查、可 `undo`。
  3. 按 `entity_key` 定位时，键值按同值判据比（文本做 NFC 后逐码点比较）。
  4. 首次创建的回执列出已有的键（已有规则），让写错当场被发现。
- **不采纳甲的理由**：改键之后再删掉那次改键的证据，键要落回旧值，而旧键此时可能已经被另一个实体占了；这需要一套"键冲突时怎么办"的删除规则。发生频率低，第一版不为它引入这套规则。
- **留位**：将来的 `rekey` 是一次新的写入意图或 op 参数，新增即可，不改已有事件。
- **第一版**：做（乙）。

### 决定 13 幂等重放返回什么

- **决定**：命中请求键时返回 `replayed: true` 与下面的内容，不再执行。
  1. **按日志重建的**：操作号、每个 op 的逐字段结果（状态、值、区间）、当时得到的 `ver`、新建的行 / 实体 ID、当时生成或并入的事项 ID、`warnings` 里由事件能得出的部分。
  2. **不重建、在 `omitted[]` 里列明的**：`affected_reads`（由读取记录算出）、派生值的改前改后值（派生写入只记校验和）。调用方需要时自己读。
  3. **事项只给当前状态**（`open` / `resolved` / `superseded`，已解决的附处理方式），**不给事项版本**。写入进了待确认、后来被拒绝，窗口内原样重发时，调用方因此看得到"提议已被拒绝"。
  4. 重放回执里的 `ver` 与事项都**不算"读到"**，不参与兜底。
  5. 原写入的内容已在某次已确认的删除里：照现行规则返回 `original_deleted`，不回显内容。
- **疑问 3（窗口内两笔内容相同的真实写入）**：服务端算出的请求键包含证据原文，两次都由同一句证据产生才会相同，那几乎总是重发。真的又发生了一笔而证据一字不差时，Agent 要带一个不同的 `idempotency_key`；工具描述写明"`replayed: true` 表示没有新写入"。
- **契约**：重放回执的形状（`omitted[]`、事项状态）。
- **第一版**：做。

### 决定 14 草稿里出现第一版不支持的键

- **决定**：`reextract`（含 `from: []` 的纯补抽）、`extends`、`compatibility`、沙箱函数规则、改表的时间类型等，出现在草稿里时整份草稿报 `not_in_this_version`（`reason: "parameter"`，`param` 指到那个键），不产生任何事件。只想加一个可选字段，就不写 `reextract`。
- **理由**：悄悄忽略 `reextract` 会让 Agent 以为旧行会被补抽。
- **第一版**：做。

### 决定 15 改动分类：穷尽的表

落在 `07-schema-evolution.md`「改动分类」，替换原来举例式的表。每种改动给：类别（只改元数据 / 确定性转换 / 重新抽取）、是否建新物理表、对旧 `sv` 的写入是否兼容、默认是否自动生效、第一版是否支持。要点：

- 新增表、新增可选字段、改说明、未被使用的改名、放宽约束、改 `duplicate_keys`：只改元数据，默认自动。
- 删表、删字段、改 `together`、改事件类表的 `time.field`、slot 改名：只改元数据，要确认。
- 同量纲改单位、带 `migrate` 的改类型、换量纲、收紧约束（带 `backfill`）、减小 `scale`、新增必填字段、改派生规则、改 slot 时区：确定性转换，要确认。
- 增删改 `entity_key`、改 `granularity`、改表的时间类型、改 `ref` 的目标、`base` 与 `derived` 互换、`ref` 与其他类型互转：第一版不支持（`not_in_this_version`；后两种任何版本都要删了重建）。
- 删除有依赖的对象（被 `ref` 指着的表、被派生规则 / `entity_key` / `time.field` / `duplicate_keys` / `together` 用到的字段）：编译失败，除非同一份草稿里依赖方也一并改掉。
- `migrate` 表达式引用别的字段时，转换结果的值来源 = 被引用字段在该行上**当时生效的**贡献（不要求出自同一次写入）。

### 决定 16 旧名、改时区、取值范围

1. **旧名**：写入按请求带的 `sv` 解析名字，任何版本的名字都认。不带 `sv` 的读取：一个名字若是某个字段在**最近 10 个 schema 版本**内用过的旧名、且当前没有别的字段叫这个名字，就按旧名解析并在 `notices` 里提示新名。当前名优先。
2. **改 slot 时区**：基础数据不动。`date` 字段的值是日历日，不重算；状态类表的 `date` 粒度区间同理。要重建的是**按 slot 时区把时刻归到某一天的派生表**（规则里对 `zoned_datetime` 取日、分桶的），以及事件类表按日期开窗的语义。归为确定性转换、须确认，是因为之后"今天""哪一天"的含义变了。
3. **取值范围**：`integer` 64 位有符号；`decimal` / `quantity` 整数部分至多 18 位、`scale` 0–12；`text` 至多 8 KB（UTF-8）；枚举至多 200 个取值、每个至多 64 个字符；名字至多 63 个字符；说明至多 500 个字符；`date` 0001-01-01 至 9999-12-31；`zoned_datetime` 毫秒精度。
4. **名字的写法**：表名、字段名、slot 名匹配 `[A-Za-z][A-Za-z0-9_]{0,62}`（受限 SQL 里直接当标识符写）；另有保留名（契约已定）：不得以 `_` 开头，字段名不得是 `valid`、`valid_from`、`valid_to`。

### 决定 17 单位同义表

- **决定**：`units@1` 给每个单位代码列出字面命中认可的写法（拉丁字母不分大小写），清单见 `10-types-and-units.md`「单位同义表」。要点：
  - 货币符号可以写在数字前面（`¥45`、`$12.5`）；其余单位写在数字后面，可隔空白。
  - CNY：元、块、块钱、圆、人民币、RMB、CNY、¥、￥。其余货币只收代码与最常见的一两种写法；没列的货币只认 ISO 代码。
  - "斤""两""亩"这类不在词表里的单位不收（数值与词表单位不同，命中会是错的）。
  - 单位 `1`（计数）不要求单位写法，数字命中即可。
- 同义表随核对器版本走（`literal@1` 含 `units@1`）；改同义表就是出新的核对器版本，旧事件里记下的命中结果不变。
- **第一版**：做（记录）。

### 决定 18 审查的疑问 3、4、5、7

- **疑问 3**：见决定 13。
- **疑问 4（改名"按名字消费"怎么判）**：接口上读写都用名字，所以"按名字读写过"就是"读写过"。把判据收窄为**提交者以外的连接实例**最近 30 天读写过这个字段：只有自己在用的字段，改名不用确认；别的 Agent 也在用的，要确认。
- **疑问 5（`undo` 带过期 `ver`）**：`undo` **不做 `ver` 冲突判定**，`ver` 可以不带。调用方点名了要撤回的那次写入，默认只撤回它仍然生效的部分，别人在它之后写的值不会被动；要动就得 `include_later`，那是高影响。`undo` 仍要过依赖状态的校验（行已撤销时报 `revoked`）与高影响判定。
- **疑问 7（"不多删"的括号）**：改写这条性质。准确的说法是：**值来源里不含被删源数据的贡献不会被去掉**；但它在哪些业务时刻上生效，可能因为挡点重算而变（一个被删写入原本挡住了某次默认终点的写入，删掉后那次写入延伸过去，盖住了别的完好贡献）。这是值的变化：实体换新 `ver`，预览里按"重新分段"列出；删除不新增 `possibly_affected` 标记（只撤不增）。

### 决定 19 前两份决定稿自身的问题

1. **W1 决定 3 的原文与推演第 4 步仍写"最大同值区间"**：已改成"以挡点为界的区间"，原始传参的写法名统一为 `corrected_span`。
2. **W1 决定 9 第 6 条与决定 22**：以 22 为准。确认一个待确认事项后，目标相交的其他待确认事项按「不过期」处理：确认者读过它们的当前版本才取代，否则刷新。规格已是这个写法。
3. **留下无值区间的撤销被 `undo`**：**不算高影响 ①**。它恢复的正是那次撤销去掉的值，两端的变化点回到撤销之前的样子，是撤销的后悔路径。撤销之后别人写进那段区间的部分照常被跳过。
4. **一次写入内事件的先后**：以事件格式 §4.2 为准——写入头最先（它的 `seq` 是操作号），然后是源数据，再逐个 op 记基础写入与它引出的事项事件，派生写入在全部 op 之后。W1 决定 19 与 `04-write-and-read.md` 原来写的"源数据在写入头之前"作废。

### 决定 20 架构负责人已定、落进数据模型的

- 纠错是标注，不是源数据的种类（由写入的意图得出）。
- 一次删除只针对一个 slot；跨 slot 的请求报 `invalid_argument`（`cross_slot`）。
- `task`、显式幂等键随那次写入的证据删除；连接实例名称不在级联范围，预览的"不会删除"里列出。
- 撤回时保持生效的写入在事件里叫 `kept_effective`；被撤回写入的字段块被删时，引用它的 `undo` 块整块列入位置列表。
- 写入事件不记写入前的值与写入后的整行；解析后的区间记在基础写入里，写入头只记原始传参。
- 物理形状变了才建新物理表；"直接切换"指不需要确认。
- 保留名、编译回执的键名、错误码、字面命中的取值、共享枚举的名字按契约与事件格式统一。

## 7. 未核实的外部事实

- UCUM 里公制单位的代码与本文所用相同（`km`、`kg`、`min`、`kJ`、`mL`、`/min`）；英制的 UCUM 代码是 `[mi_i]`、`[ft_i]`、`[in_i]`、`[yd_i]`、`[lb_av]`、`[oz_av]`；摄氏度 `Cel`、华氏度 `[degF]`。
- 换算系数：1 mi = 1609.344 m、1 yd = 0.9144 m、1 ft = 0.3048 m、1 in = 0.0254 m、1 lb = 453.59237 g、1 oz = 28.349523125 g、1 cal = 4.184 J（热化学卡）。
- ISO 4217 最小单位位数：CNY、USD、EUR、HKD、GBP 为 2，JPY、KRW 为 0，KWD、BHD 为 3。实现时应以 ISO 4217 的现行表为准生成，不手抄。
- PostgreSQL 的 `round(numeric, n)` 在恰好一半时远离零舍入。

## 8. 仍拿不准的点

1. **决定 12（键不可改）**偏保守。若评测里"键写错"很常见，撤销重写会让历史断成两个实体；届时再加 `rekey`。
2. **决定 2 的默认 `scale` 6** 是经验值；默认 `half_up` 与事件格式例子里的 `half_even` 不同，需要 R2 改例子。
3. **决定 16 的名字只允许 ASCII**：对中文用户不够友好，但受限 SQL 里中文标识符要加引号，模型容易写错。说明文字不受限。
4. **决定 11 第 6 条**让 `flagged` 事项不受"没读过只刷新"的约束，是对 W1 决定 22 的一处有意例外。
5. **决定 10** 引入了一个新的读时标注 `ref_state`，契约那边可能更愿意并进已有的标记体系。
6. **决定 1 把体积、能量、频率、速度、温度也收进了第一版词表**，比 `08-open-questions.md` 里写的"只做长度、质量、时长、货币"多。它们只是词表里的几行，不增加机制；若要收窄，删行即可。
