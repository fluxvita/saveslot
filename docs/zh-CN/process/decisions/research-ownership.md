# 决定：技术调研公开，竞品与商业研究内部

> 2026-11-12 维护者决定。本页记录调研材料的归属和维护边界，不改变产品行为、内核不变量、事件格式或操作契约。文档改动仍通过合并请求评审进入主分支。
>
> [W7 §3](pre-dev-w7-project-setup.md#3-仓库与两个远端) 中现有技术调研随主仓库公开的归属不变；本决定明确新材料的分类，不执行原提案中的目录搬迁。

## 1. 决定

1. **现有 13 份调研留在主仓库。** `docs/zh-CN/research/` 中的既有技术调研不迁移，路径与现有引用保留。公开之前按公开标准逐份通读，在原文标注已被取代的建议与未核实的判断，不改写原结论、不删除历史。本次没有替代这次通读，也不声称原有报告全部核实。
2. **技术调研继续进入主仓库。** 数据模型、存储、协议、评测方法等技术调研放在 `docs/zh-CN/research/`，按完整提交历史将来会公开的标准审查，通过合并请求交付。背景报告不取代规格的权威定义。
3. **竞品与商业研究进入内部仓库。** 从现在起，竞品分析、市场与产品快照、产品定位、收费与商业策略类调研写入另一个不公开的内部仓库，不进入主仓库。这个边界适用于新写的材料，不是把既有技术报告重新归为私有。
4. **混合调研按内容拆分。** 同一任务包含两类内容时，技术部分进入主仓库，商业部分进入内部仓库，各自成文、分别维护，不保留两份同步正文，也不把内部商业判断复制成公开技术依据。
5. **公开设计的依据必须公开自足。** 公开设计依赖的结论必须在主仓库的规格、决定稿或公开技术调研中独立成立，不得以内部调研作为依据。公开读者无需内部仓库权限，也无需把两个仓库并排克隆。

## 2. 理由

现有 13 份报告都是技术调研，已经被规格、讲解与决定稿大量引用，而且处在将来整体公开的提交历史中。搬走正文不能让旧内容重新保密，却需要逐条提炼公开依据、修改大量引用和维护跨仓库交付，成本高、收益小。因此不迁移旧目录；真正需要分流的是尚未写入主仓库的竞品、市场、定位与商业研究。分类维护既保留技术依据的可读性，也避免把不应公开的内部判断先写进公开历史，再试图用删除文件补救。

部分旧报告包含当时的建议、未核实项或临时实验，不能因继续公开就提升为现行规则或已验证结果。公开前的通读要补充状态说明和适用边界，保留原始结论及其历史上下文；涉及行为变化时，另按规格先行的流程处理。

## 3. 公开依据的约束

以下办法不能用来代替分类与公开论证：

- 将公开文档的链接换成私有仓库链接，或要求贡献者取得内部访问权才能理解或实现设计。
- 在规格中写「以内部调研为准」；内部报告不能补充公开规格没有写明的规则。
- 在两个仓库各维护一份完整且持续同步的正文；混合报告应拆成职责不同、各自完整的文档。
- 将历史观测、未入库原型或已删除的临时脚本，重新包装成已经通过、可以复现或具有统计代表性的实验。

支撑公开保证的规则、已采纳理由、外部原始出处以及必要的实验方法与限制，应在公开文档、代码和测试中提供。原始实验资产缺失时如实标明，是否补脚本或重新测量单独交付，不通过改变材料位置掩盖证据缺口。

## 4. 维护入口

| 入口 | 归属说明 |
|---|---|
| `AGENTS.md` | Agent 必须按技术 / 商业分类提交；公开设计不依赖内部报告 |
| `CONTRIBUTING.md`、`CONTRIBUTING.zh-CN.md` | 人与 Agent 遵循相同的研究归属边界 |
| `docs/zh-CN/guide/12-contributing.md` | 目录职责、混合报告拆分与旧材料公开前复核的说明 |
| `.gitlab/issue_templates/Research.md` | 技术调研交付到 `docs/zh-CN/research/`；竞品、市场、定位等不在本仓库交付 |
| `.github/ISSUE_TEMPLATE/research.md` | 与 GitLab 模板采用相同边界 |
| `docs/zh-CN/process/README.md` | 指向本决定，不再将其标为待讨论的搬迁提案 |

主仓库原有 `research/` 导航、W7 归属与技术文档引用不因本决定改址。内部报告的收录沿用内部协作规则；本决定不自动批准某一份报告，也不改变其核验状态。

## 5. 历史与实施范围

**删除当前文件不会删除 Git 历史。** 本决定既不迁移现有 13 份报告，也不要求改写历史或强推主分支。若公开前发现真正不应公开的信息，走独立的信息安全与公开前审查流程，不把普通文档整理说成已完成保密处理。

本次交付是决定稿、目录职责和模板说明；不包含现有调研的逐份复核，不改动原有研究正文、不移动其路径，也不改变产品代码或行为规格。旧报告的公开前通读是后续工作，不因本决定入库自动视为完成。
