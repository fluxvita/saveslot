# 决定稿：回掉按（事件, 目标）记，不按下标

> 状态：草稿，待评审。通过之前不改规格与事件格式。
> 涉及：`spec/03-data-model/03-deletion.md`、`spec/03-data-model/04-write-and-read.md`、`spec/03-data-model/01-objects.md`、`spec/03-data-model/02-integrity-and-records.md`、`spec/03-data-model/05-time.md`、`spec/09-event-format.md` §5.7 与相关块；参考求值器。逐处见 §7。

## 1. 问题

回掉（`undo` 与 `take_previous`）的回退记录逐项列（事件, 字段或"存在", 下标）。删除重放时一次写入的项会分裂、合并、重新编号，记录里的下标在重放里覆盖哪一块，要靠一组规则推：新编出的下标从哪一项分出、展开覆盖哪些项、几项落进同一段时切不切、切点放在哪、原有项落在哪一段。

这组规则一直在补，每一次都对应一个违反「顺序无关」或「撤回还原」的反例。到"一律以写入时的区间块为准"仍有两类覆盖不到：

- 回掉写在某次删除之后，记录里直接列的就是那次删除编出的下标，它没有写入时的块可依；撤回那次删除再重放，这次回掉不再覆盖任何东西。
- 回掉写入时，一项已被一次待执行的删除并掉，记录没列它；之后任何一次重放都会按写入时的块让它重新出现、且不被覆盖，连删一个日志里从未引用的来源都会改变结果。

根子是：**下标随删除历史变，而规格把"人决定回掉什么"落在了下标上。**

## 2. 前提：人的决定以（操作, 目标）为单位

一次写入写进来时，可能一部分生效、一部分成为候选或待确认。之后人撤回了这次写入；再之后某次删除去掉了与它冲突的写入，重放里原来的候选部分变成生效。这部分算不算已被撤回？

- 照记录：不算。人撤回时只看到生效的那部分。删除之后，一次已撤回的写入会有一段内容重新出现，且没有任何写入能再撤回它。
- 反事实：算。假如被删内容从未存在，人当时看到的就是整次写入生效，撤回的就是整次写入。

**取反事实。** 人的决定记录的是"回掉哪几次操作在哪些目标上的改动，回到哪个位置的状态"，不是"回掉当时列得出的那几项"。被列入的操作与目标照记录、不因删除增减；回掉的范围与那里的值在重放里重求（这一半不变）。

两条边界：

- **不在记录里的操作不补。** 回掉之后才因删除生效、记录里没有的操作，仍按"记录之外的写入"处理（排在记录里某次操作之后时盖住它，由它生效）。
- **连带回掉有域。** `include_later` 连带的后来写入只在"与被撤回操作相交的字段与区间"上回掉（04-write），这个"相交"按被撤回操作在重放里**生效过**（在"在"里）的项与步骤 3 的取代关系算（§3.2 的域）；`take_previous` 只在事项的区间上回掉（现有的域）。

## 3. 做法

### 3.1 回退记录列什么

回退记录的条目是（事件, 目标），目标是字段或"存在"；不再有下标。另带两个照记录的标注：`later`（这一条是 `include_later` 连带的后来写入）与 `skipped`（写入时被跳过，只供历史与回执）。列法：

- **`undo` m，m 是普通写入**：m 在这一行上每条基础写入 e、e 的每个目标 t（不论写入时生效、佐证、候选、待确认或被跳过；来源键字段除外）。
- **`undo` m，m 本身是一次回掉**：m 的基础写入 e、**m 的回退记录里出现过的每个目标 t**（含"存在"），不论 m 写入时在 t 上有没有写回项。这样 m 之后因删除在别的目标上长出的写回项也被覆盖，现行伪代码步骤 1 的例外由这条取代。m 当时没有写回项时仍按 04-write 不能 `undo`（`invalid_argument`），"当时"按这次 `undo` 写入时的状态判、含待执行的删除：待执行删除把 m 的写回项全部重述成 `dropped` 时被拒（现行例外原来允许这种情形，现在明说不允许）；待执行删除让 m 有了写回项时被接受，之后撤回那次删除，这次 `undo` 覆盖空集，末端与它从未被接受相同。m 是经确认生效的待确认回掉时，取确认触发的那条基础写入与它的回退记录（09 §5.8），不取提议那条。
- **`include_later` 连带的后来写入**：照现行规则挑（写入或确认时，后来的某一项生效（`applied`，不含佐证）、按步骤 3 取代被撤回操作某个生效项、且区间相交），列（该项的基础写入 e′, 该项的目标 t′），标 `later`。t′ 不必是被撤回操作的目标：后来的撤销取代被撤回操作的字段项（列 (e′, 存在)），后来的填值或恢复存在取代被撤回操作的撤销（列 (e′, 字段) 或 (e′, 存在)）。后来的写入本身是回掉时，同样按它的项挑，条目取（它的基础写入, 该项的目标）。
- **`take_previous`**：事项的冲突单元与区间内、合并基之后解决之前有项生效过的（事件, 目标），同现行规则去掉下标。

### 3.2 覆盖与域

回掉 n 在目标 t 上覆盖的项：

- R′ = { c ∈ C | （c 的事件, c 的目标）∈ R }：记录里每条（e, t）在重放里的**全部项**，不论下标是写入时就有的还是删除编出的，不论写入时的状态。
- 在 = [ r ∈ R′ | r 的状态是生效或佐证 ]（不变）。仍是候选、待确认的项不在"在"里，不登记、不写回；因删除生效的项进"在"。
- 域：
  - `take_previous`：不变（重放里仍存在的各候选的区间之并；K = 本事项里各候选写入在该冲突单元上的项）。
  - `undo`：对被撤回操作自己的条目，域是全部业务时间（不变）；对标 `later` 的条目里的项 x，域是 D(x) = ⋃ { 区间(r) | r 在"在"里、r 不标 `later`、x 按步骤 3 取代 r }，即被撤回操作在重放里生效过、且 x 能取代的那些项的区间之并（x 只取 `applied` 的项，与步骤 3 的"x 的状态是生效"一致）。事件类表、无时间表上 D(x) 是 ⊤ 或 ∅。只取"在"里的项：写入当时只在被撤回操作真正生效过的区间上连带回掉（它当时是候选的部分从未生效，不算"相交"）；删除让那部分生效后它进"在"，D 随之变大，反事实读法照样成立。
  - **写入当时的行为因此变窄**：现行求值器把被选中的后来项整项回掉，现在只回掉 D(x) 之内；超出被撤回操作区间的部分照旧生效（04-write"在相交的字段与区间上一并回掉"本来就是这个意思）。依赖整项回掉的固定用例逐条重看。
  - **高影响 ④ 的判据**：有标 `later` 的项范围非空（不再是"在"里有后来的项）。05-time"④ 要回掉的后来写入全被删除时同理"改写为"标 `later` 的项在重放里范围全为空时同理"，全被删除是它的特例。
  - **④ 的判据在写入当时也会变**：后来项 V 在写入当时已被一次不在记录里的写入整个盖住时，现行规则仍进待确认，新判据下 V 的范围为空、不触发 ④、直接生效（实际上没有后来的值被回掉）。反过来，删除让某次记录之外写入的默认终点延伸、盖住 V 时，一次待确认的回掉不再属高影响、在自己的写入号生效；预览写明原因。
  - 范围(r) = (区间(r) − 盖住(r)) ∩ 域(r)。

伪代码的改动：

- 步骤 1：R′ 按上式；"新编出的下标"的展开与"写入时没列入的下标不补"删去；目标是回掉时的例外删去（§3.1 已含）。
- 步骤 2：域按上式，`undo` 的 `later` 条目用 D(x)。
- 步骤 3：x ∉ R′ 改为（x 的事件, x 的目标）∉ R。
- 步骤 5：登记的对象仍是"在"里的项，各在 区间(r) ∩ T(t) 上；不登记"在"之外的项（含落在别的条目范围里的候选）。
- 步骤 6："以写入时的区间块为准"一段中，关于展开是否覆盖、切点资格与位置、"几条原有项落进同一段时覆盖不同就切开"的内容删去；编号规则与"新编出的下标从哪一项分出"（按写入时的区间块判）保留（§3.3、§3.5）。写回项仍按"相邻、内容与给出者都相同的并成一项"。

### 3.3 下标与分项

同一（事件, 目标）的各项被同一组回掉覆盖、域按区间作用于登记，所以**不再有因覆盖不同而切开的情形**：几条原有项落进同一段时一律并成一项，留下标最小的，其余重述为 `dropped`。

分项与编号的其余规则不变，仍对任何写入的项适用：一项在重放里的区间是它的状态与内容相同的极大连续段（写回项的"内容"含给出者：给出者不同的相邻段不并，否则 `carried` 只剩一个，删掉另一个给出者时级联不对）；原有项留在与它写入时区间块相交的第一段上并沿用下标；新分出来的项从该目标已用过的最大下标之后接着编；最近一次给出的块只用于删除编出的下标保留编号。

下标仍是寻址：重述、`carried`、`deps`、`candidates/<k>.items`、`kept_effective/<k>.items`、前提声明第 2 部分的 `premise_covers` 都按下标引用。**本稿只把回掉的覆盖从下标上拿下来**，这些引用在删除下怎么跟随不在本稿范围（见 §6）。

**偏离二按写入时的区间判，不按幸存的下标判。** 合并之后，一项写入时生效的部分与一段写入时是候选、因删除才生效的部分可能并在同一个下标下；之后另一次删除让后一段应回到候选时，按写入时的区间块判它从未在写入时生效，不因与生效部分同号而受保护（参考求值器的 `recordedStatus` 已按写入时的块判，规格写明）。

### 3.4 生效状态的判定次序

"在这次重放的结果里生效的回掉"按操作号逐个判定（判第 n 个时，早于它的按已判定的状态算，它自己按生效算）这一条保留。它现在写在 09 §5.7 那段下标规则中间，改写时挪成单独一段，05-time 高影响 ④ 的引用改指那里。

### 3.5 前提声明

02-integrity「覆盖、取代与清除」第 1 部分（本 op 自己写下的各项）按（事件, 目标）覆盖：本 op 在该目标上的全部项。第 2 部分（op 所见版本上已生效的其余各项，"之后生效的不补记"）不变，仍按记下的项；删除编出的下标随它所分出的那一项一并被覆盖，"从哪一项分出"按写入时的区间块判（保留现行规则，只用于这里与编号）。

## 4. 逐条对照

| 要满足的 | 为什么成立 |
|---|---|
| 顺序无关（比状态与事项，不比下标） | 覆盖由记录里的（事件, 目标）、重放里的项与它们的区间决定，域 D(x) 也只取重放里的区间；这些都只取决于当前被删集合。切开不再依赖任何块的历史 |
| 撤回还原 | 同上：给定记录，覆盖与被撤回的删除无关。**记录本身**（列了哪些操作）是写入时定的，写入时一次待执行删除藏起了某次操作，它就不在记录里，撤回删除后它作为记录之外的写入出现——与宽限期内写入的现行定义一致，不算违反 |
| 不漏删 | 不再有从块推出的切点与位置；写回项的区间与端点仍按步骤 6、8 取自取值位置上的贡献 |
| 人的决定照记录 | 被回掉的（操作, 目标）照记录；连带回掉的项只在 D(x) 内，即被撤回操作生效过、且它取代的区间；取值位置照记录 |
| `undo` 回得干净 | 被撤回操作每个目标上的每一项都被覆盖；撤回一次回掉时覆盖它记录里的全部目标 |

## 5. 不选的做法

- **继续按下标补规则**：已补了六轮仍有两类覆盖不到，不能确定收敛。
- **另记回掉当时覆盖的业务时间范围**：范围在决定当时的被删集合下算出，撤回那次删除后仍带着痕迹；撤回一次全被跳过的回掉时范围为空；要新增一类数据块。
- **连带的后来写入也按整次操作覆盖**：会在写入当时就抹掉与被撤回操作不相交的、记录之外的写入（Z 不在记录里、区间与被撤回操作不相交，却因 V 的另一项被覆盖而被写回盖掉），违反 04-write"在相交的字段与区间上一并回掉"。

## 6. 不在本稿范围

- **"写到已被整行删除的行报 `not_found`"按什么判"已被整行删除"**：现在随删除历史变，应按当前被删集合下的重放判，另行裁定。
- **其余按下标的引用在删除下怎么跟随**：`kept_effective`、`candidates`、前提声明第 2 部分、`carried`。它们与回掉的覆盖可能有同类问题（随删除历史变），另行检查；参考求值器里 `kept_effective` 按（事件, 目标）记，与规格的按下标不一致，一并定。§3.3 的一律合并会让"下标指向重述为 `dropped` 的项"更常出现，`kept_effective` 与 `carried` 首当其冲。
- **参考求值器接受对全部被跳过的 `undo` 再 `undo`**，与 04-write 的 `invalid_argument` 不一致：求值器改为与规格一致（日志里不会出现这样的写入）。

## 8. 待评审的问题

1. 合并之后挡点变化是否影响任何已定的性质或事项（固定用例逐条重看时确认）。
