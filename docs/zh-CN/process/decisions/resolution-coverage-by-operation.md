# 决定稿：冲突解决的覆盖也按操作记，不按下标与区间

> 状态：已采纳。
> 前提：[`revert-coverage-by-operation.md`](revert-coverage-by-operation.md)（回掉按（事件, 目标）记）已采纳。偏离二的保护范围在删除下怎么取（写入时状态不同的两段之间的分界点出自被删内容时）见 [`protection-unit-after-execution.md`](protection-unit-after-execution.md)，本稿不依赖它的结论。
> 涉及：`spec/03-data-model/03-deletion.md` 伪代码步骤 2 与「重放规则」；`spec/03-data-model/01-objects.md` `take_previous`、`take_candidate` 与影响表；`spec/09-event-format.md` §5.7 与事项的 `candidates` 块；参考求值器。

## 1. 问题

冲突事项的两种触发写入的解决方式，在删除重放里各有一处落在会随删除变化的东西上：

- **`take_previous` 的域按候选的下标求。** 域 = 事项各候选项的区间之并，候选项按下标记。删除让同一次候选写入的几项合并、留最小下标时，被记下的下标可能成了 `dropped`，域变小乃至为空，`take_previous` 回掉不了它本该回掉的范围。例（状态类表 f2）：#11 f2=1（S1）[11-03,11-11)；#21 f2=3 [11-09,11-20)；#31 f2=5 [11-15,11-18)；#61 f2=1 显式、所见 ver 10、[11-03, next_change)：写入时 [11-03,11-09) 佐证、[11-09,11-11) 候选；操作 100 `take_previous`。删 S1 后被记下的候选下标被并掉，#21 不再被回掉。
- **`take_candidate` 没有界。** "状态类表按候选区间执行"，候选的区间在重放里重新求；删除让候选延伸时，采纳的值随之延伸，盖掉用户解决时没看到、影响里也没列出的写入。同一例改用 `take_candidate`：不删时结果是 [11-03,11-11) 1、[11-11,11-15) 3、[11-15,11-18) 5、[11-18,11-20) 3；删 S1 后整段 [11-03,∞) 是 1，#31 的 5 与 #21 在 [11-11,11-20) 的 3 都被盖掉。

## 2. 原则

与回掉相同：**人的决定照记录的是操作，范围与值在重放里重求；被决定涉及的操作照记录，不因删除增减；记录之外的操作不补。** 反事实读法照用：被采纳或被关闭的那次候选写入，删除让它在本事项里多出来的部分，同样算在这个决定里。

## 3. 做法

### 3.1 K：本事项的候选项按"由本次解决关闭的项"取

事项解决时照记录的是**这一刻事项里实际在的（事件, 目标）**，不是下标，也不是候选写入整体：被采纳的、被这次解决关闭而没采纳的都在里面（`keep_effective` 与 `take_previous` 同样记）。任何一次重放里，K = 记下的（事件, 目标）在重放里的项。解决时不在事项里的目标（被一项待执行的删除去掉、撤回后放回的）不在 K 里、也不被这次解决关闭，按「撤回与宽限期」另判、另开事项。

**人做过决定的（事件, 目标），之后任何重放都照那次决定的记录**：不看它写入时是候选还是待确认，也不看重放里冲突的成因还在不在（01-objects「处理之后事项不重开」；03-deletion「人已经解决的冲突，照记录」）。确认记下判定时实际在待确认的（事件, 目标），重放里这些项保持被这次确认关闭，确认照这些项执行；拒绝针对整次写入：被拒绝的写入在任何重放里各目标都不生效、保持已关闭，只有写入时就生效或成为佐证的部分照旧（03-deletion「冲突消失之后」）。唯一先于记录的是同值规则：重放里与写入方所见版本整段同值的项不是一次改动（没指证据的不再是贡献；指了证据的，到写入那一刻仍同值的部分是佐证，已被改过的部分仍是改动、照记录），没有要决定的东西。

归属：
- 一项至多归属一个事项。撤回删除时放回、另开冲突事项的目标不在之前任何解决记下的项里；由待确认转为冲突、归给接替事项的项不算别的事项的，**接替事项自己的解决里它在 K 里**（那次解决记下的就是它）。
- 已被这次解决关闭的候选写入，因删除延伸出的部分仍归属本事项，不并入同一单元上别的未决事项（01-objects「处理之后事项不重开」：没被采纳的候选不再出现在任何未决事项里）。
- 冲突单元是"存在"的事项取候选写入在"存在"上的项与字段上的项；同一写入在某个字段上另有字段单元的事项时，**按解决时记下的单元**：归属在写入时判定、按（事件, 单元）记（某处与期间的撤销冲突的归存在事项；只与期间的字段修改冲突的归字段事项；两者都有的归存在事项；字段组里任一字段碰到撤销，整个单元归存在事项），之后的重放照记录，不按重放里的冲突成因重分——否则删掉当初冲突的那次写入，候选的成因只剩撤销，人做过的采纳整个消失。

`take_previous` 的域 = K 的区间之并（步骤 2 改读这个 K）。事项的 `candidates/<k>` 仍列每一项的值与区间（事项内容、确认哈希要用），另记（事件, 单元）作为 K 的标识；重放里取 K 只看标识，不看下标。

### 3.2 `take_candidate`：照记录的覆盖集 O 与合并基

`take_candidate` 的解决记录，都在解决那一刻（实际历史上的状态，含当时已确认的删除）判定一次，之后照记录：

| 记下的 | 是什么 | 性质 |
|---|---|---|
| 解决记下的项 | 这一刻事项里实际在的（事件, 目标）（§3.1） | 标识 |
| 合并基 | 与 `take_previous` 一样，不重算 | 标识 |
| 覆盖集 O | 列法与 `take_previous` 的回退记录相同：事项的冲突单元与区间内、合并基之后解决之前有项生效过的（事件, 目标） | 标识 |
| 采纳时填上的撤销 | 状态类表上，这一刻在生效、与被采纳项的范围相交的撤销，按（事件, 目标）记下当时的区间 | 含抄下的区间 |
| 因待执行的删除而不在生效的项 | 这一刻有删除待执行时：把它们都撤回所得的状态里生效、而实际状态里不在的项（被删除直接去掉的，或自己的来源没被删、因删除改了判定而不在生效的），按（事件, 目标）记下当时的区间 | 含抄下的区间 |

这几样是解决记录的一部分。抄下的区间属于数据块，随所抄内容的来源被删而清除（03-deletion「不漏删」里"回退与删除结果里抄下的区间"同一类）。

重放时，采纳写下的项：
- **值与来源**：被采纳候选的值；值来源是事项里与它同值的全部候选（03-deletion「搬运的值」的"任一仍在即在"）。
- **区间**：逐目标判。被采纳候选写入在该目标上 K 内各项（重放里）的区间之并，扣除盖住的部分。**只有被采纳写入在该目标上没有 K 内的项时**（全被删，或被放回后归了另开的事项），才退到同值候选：取事项里与它在该目标上同值的候选写入在该目标上 K 内各项的区间之并（"同值"按目标比，字段组不要求整组同值）。反事实依据：假如被采纳那次写入从未存在，事项里与它同值的候选就是这个决定采纳的值（03-deletion「搬运的值」"任一仍在即在"）。代价：退路可能落到同值候选独有、用户解决时没在"采纳会覆盖的段"里看到的区间，覆盖那里 O 内的写入；预览单列（§3.4）。
- **盖住**：按步骤 3 的取代关系逐目标判。合并基之后、本次解决之前生效、且（事件, 目标）不在 O 里的写入，在它取代采纳项、**而它自己没有被更晚的 O 内写入取代**的地方盖住采纳项，由它照常生效（被 O 内写入压在下面的 O 外写入若也算，会在采纳项上挖洞、露出用户决定盖掉的 O 内的值）。采纳是宽限期内生效的写入时，记下的「因待执行的删除而不在生效的项」在记下的区间内不盖住它（被覆盖的部分以宽限期内的写入为准）；回来时本身不在生效、之后因别的删除才生效的项不在此列。事件类表上存在与字段值互不相盖：O 之外的字段写入不盖住被采纳的撤销，只有 O 之外此刻生效的恢复存在才让它不再算。字段上的采纳与撤销：解决时撤销不盖住（按对当前状态的校验处理）；重放时，状态类表上不在 O 里的撤销只在采纳时填上的区间之外盖住（解决时没生效、因删除才生效的整段盖住，已生效而区间变长的多出部分盖住，填上的部分不盖）；事件类表上撤销不是字段上的值项，不盖住，采纳的值留在字段上、行仍是已撤销。采纳的是撤销时，盖住它的是恢复存在与空洞里的填值，被填值盖住的那一段按普通的"撤销之后在空洞里填值"规则取值（与被采纳的撤销写在它自己的操作号、之后被填上相同）；存在单元上采纳修改时补出的合并基必填字段，取值位置照记录在合并基、值在重放里重求，区间与盖住同上。
- **依赖**（`deps`）：K 内的各项、同值候选、盖住它的非 O 写入、区间被截断处的截断者。

不记解决时的区间：那个区间的端点可能出自之后被删的内容（上例的 11-11 出自 S1），记下来会违反"不漏删"。

### 3.3 宽限期内的决定与原事项

宽限期内人做的决定（解决、确认、拒绝）在撤回后保持（03-deletion「撤回与宽限期」）。它关闭的项若是另一个事项的候选（例如写入时是候选、因删除转成待确认后被确认的写入），撤回后那个原事项不再有候选，保持「已被取代」，原因写那次决定：这是「宽限期内有写入按冲突判据改过它涉及的字段的，保持已被取代（原因写那次写入）」的直接适用，确认与采纳写下的项就是那次写入；拒绝没有写值，原因写那次拒绝。参照用的强制重放照宽限期内各决定的记录执行（针对哪些项、是哪一种决定），值与区间在参照里重求。

### 3.4 预览与回执

删除使 `take_previous` 的域或 `take_candidate` 的采纳区间变化时（扩大、缩小、改按同值候选落），不另过高影响判定（与回掉的范围同一口径：范围不是决定的一部分；扩大部分即使抹掉变化点、填上无值区间也照落），`deletion_preview` 与删除回执单列，附受影响的写入。

### 3.5 §1 两例（不涉及偏离二保护范围的部分）

删 S1 后，#61 在 [11-09, ∞) 上的部分（写入时 [11-09,11-11) 是候选、延伸出的部分是已关闭候选的延伸）都在 K 里；[11-03,11-09) 写入时是佐证，它在删除后怎么判属于另一稿，下面不列。
- `take_previous`：域 = [11-09, ∞)；#21 在域内被回掉，取值位置是合并基处，那里出自 S1 的值已删，写回"没有值"；#31 不在回退记录里，在 [11-15,11-18) 盖住，5 照常。结果：[11-09,11-15) 无值，[11-15,11-18) 5，[11-18,∞) 无值。
- `take_candidate`：采纳区间 = [11-09, ∞) 扣除盖住；#31 不在 O 里，[11-15,11-18) 盖住采纳项，5 照常；#21 在 O 里被覆盖。结果：[11-09,11-15) 1，[11-15,11-18) 5，[11-18,∞) 1（[11-20,∞) 是填上无值区间，照落，预览单列）。

## 4. 逐条对照

| 要满足的 | 为什么成立 |
|---|---|
| 顺序无关、撤回还原 | K 与 O 由记下的事件、单元与按当前被删集合的重放决定，与删除先后、撤回过什么无关 |
| 不漏删 | 不记区间；域与采纳区间都取自重放里的项 |
| 人的决定照记录 | 被关闭 / 被采纳的候选写入与 O 照记录；O 之外的写入在采纳区间里照常盖住，不被用户没看到的决定改动 |
| 确认绑定内容 | 解决时带回的事项版本照旧绑定影响；写入当时采纳区间就是被采纳候选在 K 内的区间，不超出影响里"采纳会覆盖的段"。之后范围的变化是重放结果，与回掉的范围同一口径（不是决定的一部分），预览单列；同值候选退路可能落到用户没看到的段，是采取反事实读法的代价 |

## 5. 不在本稿范围

本稿的定义不依赖偏离二那一稿，但结果会随它变：K 跟着重放状态走，一次写入写入时一部分是佐证、一部分是候选时，删除之后哪部分算候选取决于那一稿的结论。这类混合写入目前没有固定用例，随那一稿补。

- 偏离二的保护范围在删除下怎么取：写入时状态不同的两段之间的分界点出自被删内容时（保护整段会漏删、整段不保护会让已生效的写入退回），已定：保护的单位取一次写入在一个目标上的全部项，见 [`protection-unit-after-execution.md`](protection-unit-after-execution.md)。
`kept_effective`、前提声明第 2 部分的 `premise_covers`、`carried` 在合并时可能丢引用（被并掉下标上的引用没有转给留下的下标）。它们在参考求值器里没有按下标建模，目前只有规格层面的推演，另起一稿。
