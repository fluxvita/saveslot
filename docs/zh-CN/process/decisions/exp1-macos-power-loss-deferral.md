# 决定：实验 1 的 macOS 真机断电推迟到第一次对外发布本机模式之前

> 2026-11-12 维护者决定。这是对 [`pre-dev-w0-experiments.md`](pre-dev-w0-experiments.md)「实验 1」做法的一处偏离：**通过标准不变，改的是 macOS 真机断电这一步在什么时候做、挡住什么。** 结果报告见 [`../experiments/exp-1-pglite-durability.md`](../experiments/exp-1-pglite-durability.md)。

## 1. 决定

1. **P1 `store` 收尾时不等 macOS 真机断电。** 实验 1 在 P1 收尾时的判定，macOS 一侧以步骤一与步骤二为凭：
   - 步骤一：组 B 每个提交在确认前都对预写日志发出 `F_FULLFSYNC`，组 A 一次都没有（标准 1）；
   - 步骤二：强杀 1,000 轮加两个变体各 200 轮，已确认提交零丢失（标准 2）；
   - 另以 Linux 虚拟机上组 A、组 B 两组断电作佐证。
2. **Linux 部分不放宽。** Linux 的步骤一、二、三须全部按原标准通过，其中组 A 的阳性对照（至少丢一次已确认提交）必须成立，否则断电方法作废。
3. **macOS 真机断电在第一次对外发布本机模式之前补做，标准不变**：台式 Mac 拔电源，组 B 20 轮零丢失，组 A 至少丢一次（标准 3、4 的 macOS 部分）。
4. **不通过就不发布本机模式。** 按实验规格「不通过时的决定」处理：本机后端换成随 saveslot 打包的原生 PostgreSQL，或修好后重跑全部步骤再发布。

## 2. 理由

- **现在做不了，而且没有合格的替代。** 真机断电需要一台台式 Mac（笔记本有电池，拔电源不等于断电）。笔记本"正常关机再开机"会先把缓存写盘，测不出问题；在工作用的笔记本上"长按电源键强制关机"也不做。
- **macOS 上的主要依据已经在手。** 实验规格本身把标准 1（直接看到落盘调用）定为主要依据，断电轮数是佐证：20 轮零失败只能粗略说明失败率不高。步骤一已直接观察到每次提交前的 `F_FULLFSYNC`，这是 macOS 上要求磁盘把写缓存刷到介质的调用。
- **风险只在发布时才落到用户身上。** 本机模式在第一次对外发布之前没有真实用户数据，推迟期间丢数据的风险只影响开发与测试。把关口放在发布前，既不让 P1 空等，也不让未经断电验证的本机模式到达用户手里。
- **不改标准，只改时间。** `07-scope-v1.md` 要求实验 1 的零丢失与必须观察到落盘调用不得放宽。本决定两者都不放宽：macOS 的断电标准原样保留，只是从挡 P1 `store` 移到挡本机模式的第一次发布。
