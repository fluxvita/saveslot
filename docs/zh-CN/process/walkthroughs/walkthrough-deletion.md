## 设定

- **部署**：第 1–6 组是云服务（PostgreSQL，单节点；有删除到期索引、删除登记、冷租户归档、调度器）；第 6 组末尾另做一段本地对照（PGlite + Time Machine）。
- **主体**：用户 `U`（用户会话）；Agent A = `MacBook · Claude Code`，scope `saveslot.read saveslot.write saveslot.schema saveslot.delete`；Agent B = `MacBook · Codex`，scope `saveslot.read saveslot.write`。删除都由 A 执行（`saveslot.delete`）。
- **日期**：2026 年。W45 = 11-02（周一）至 11-08。slot 时区 `Asia/Shanghai`。删除操作都在 11-10，宽限期到 11-11 同一时刻。
- **记号**：`#n` = 日志 `seq`；一次 `saveslot_write` 产生"源数据 → 逻辑写入头 → 基础写入 → 派生写入"几条事件，**本文只写逻辑写入头的 `#n`**，其余略。
  `s_…` = 源数据；`r…` = runs 的行，`x…` = expenses 的行，`e_…` = budgets 的实体；`pi_…` = 事项；`rd_…` = 读取；`v@#n` = 最近一次业务写入是 `#n` 的版本标记。
  初始数据按 slot 分段编号（health #1–#60、marketing #100–#140），真实日志里两个 slot 交错，不影响推演；第 1 组起的事件从 #200 往后编。
- **表头**沿用前两次推演：做了什么 | 调用 | (a) 追加的日志事件 | (b) `apply` 改的物化状态 | (c) 本地运行状态 | 回执 / 之后读到什么。
- **每步固定核对三项**（HANDOFF 第 7 条）：① 事件头里有没有由用户内容算出的值；② `verify` 报什么；③ `ver` 有没有换。结果写在每步末尾的"核对"一行，汇总见「核对汇总」。

## 场景结论

**保得住**（删掉的不回来）：宽限期内导出、到期执行、恢复晚于删除确认的备份，都不会让删除复活。**有两处缺口**：
- 恢复早于删除确认的备份，按现行设计只能暂停租户、等人处理（Q47）；
- 恢复后 `seq` 被重复使用，删除登记的位置核对会对错事件（Q46）。

另外，幂等窗口内的重发会让刚删掉的原文以新写入的身份回来（Q53）；本地两个目录被一起恢复时完全发现不了（Q60）。

**说得清**（预览、回执能让 Agent 和用户明白会发生什么）：大部分场景预览能写清。**说不清的有三处**：
- 按预览建议补了佐证、行却还是被整行删除（Q41）；
- 一次写入带两段证据时，Agent 要重新引用同一次写入里本来就有的证据（Q48）；
- 按行删除时，用户最想删的那句话不在删除范围里（Q42）。

**算得对**（删除后的状态符合规则）：事件类表、拆段恢复、`next_change` 重新解析、派生分组清空、跨版本表都算得出唯一结果。**算不出唯一结果或结果不对的有五处**：
- 回退（Q40）；
- 冲突事项失去候选（Q43）与级别变化（Q51）；
- 撤回时分组映射冲突（Q44）；
- 迁移进行中删除（Q45）。

**只靠文档能不能推下去**：1b（接替与残余）、3a（回退）、4c（失去候选的事项）、4e（迁移中删除）、5a（分组复现、写已删除的行）、6a（`seq` 复用）需要自己补规则才能往下走，其余都能直接按文档推出。
