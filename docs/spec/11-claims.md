# saveslot · Claims index

English · [简体中文](../zh-CN/spec/11-claims.md)

> The statements in the specification that are written as "in any case ...", and which test guards each. One claim per row: where the original text is, what it is compared against, which test it is, and whether it holds now. Where there is no test, "No test" is written as it is.

The rules of the specification are scattered across the chapters, and a part of them are universal claims: "the two orders reach the same conclusion", "replaying from an empty storage gives the same state". This index adds no new rules and only cross-references: where a claim is written, what kind of input could overturn it, and in which test this check runs.

This version covers three subsystems: conflict judgement, the determinism of replay (including the two storage backends), and read records and history, plus one claim on data compatibility across versions. The claims on privacy deletion and on migrations that need physical tables rebuilt are added later.

## How to read this table

- **Claim**: the original wording of the specification, linking back to the section it is in. When the original is changed, this row is changed with it.
- **Oracle**: what input, what is compared, and **what is deliberately not compared**. The half that is not compared matters as much as the half that is: if it is left out, the test turns red for unrelated reasons.
- **Test**: the file path (from the repository root) and the case name. Case names follow what is written in the source, and the names of `it.each` keep `%s`; the name of the `describe` it sits in may come before it.
- **Status**:
  - `Holds`: a property test, or a scan of all the objects, guards it within the range the oracle states.
  - `Partly tested`: there are only fixed cases, or only a part of the claim is covered; what is not covered is stated in the oracle.
  - `Known not to hold`: the specification has already written it as a claim with a range and listed the cases outside the range; this row is one of those cases, and the test asserts the result of the current rules and turns red when the rules change.
  - `No test`: no test guards it directly.
- **Belongs to**: the code in which this claim lives. This row is maintained by whoever is responsible for that code.

A merge request that changes a rule updates the rows it touches in this same file. `docs:claims` in `pnpm check` ([`scripts/check-claims.ts`](../../scripts/check-claims.ts)) checks every row: it has a number, it links back to the specification, it has an oracle, its status is one of the four above, the test file it points at exists, the case name is in the file, and it is not skipped. It does not judge whether the test passes; that is the business of the tests themselves in `pnpm check`.
